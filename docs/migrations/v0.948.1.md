## What changed

When a DesignIR document is loaded from disk, its manifest assets resolve
relative to the document's own directory. An asset `local_path` or `file://`
`original_uri` that leaves that directory is now refused, whether or not the
file exists: a `../` segment (backslashes count as separators), an absolute
path elsewhere on the host, a drive-letter or UNC root, or a symlinked
directory that points out. A matching `content_hash` does not admit such a
path, with one exception: an absolute path to a file inside Pulp's own asset
cache (`PULP_IMPORT_ASSET_CACHE`, else the per-user cache) loads when the file
hashes to the declared `content_hash`, so network assets the importer fetched
keep working. The refusal is logged:

```
design-import: asset 'logo' refused — local_path '/elsewhere/logo.png' resolves
outside the document directory '/project/design'
```

The asset then reads as unresolved, as a missing file does.

`GraphEditorView` (`<pulp/view/widgets/graph_editor_view.hpp>`), which draws
and edits a host `SignalGraph`, moved out of `Pulp::host` into a new
`Pulp::view-graph-editor` target, which links `Pulp::view-core` and
`Pulp::host`.
- `Pulp::host` no longer depends on `Pulp::view-core`.
- Neither view umbrella (`Pulp::view`, `Pulp::view-native`) links
  `Pulp::view-graph-editor`, so an ordinary view or plug-in UI does not pull in
  the plug-in host stack.
- The target is not built on iOS, where `Pulp::host` is absent. The header still
  installs.

The audio-dependent widgets moved out of `Pulp::view-core` into a new
`Pulp::view-audio` target: the meters, the waveform and spectrum visualizers,
the EQ curve, the audio inspector, MIDI binding, the plug-in manager panel and
the waveform GPU helpers.
- `Pulp::view-audio` links `Pulp::view-core`, `Pulp::audio`, `Pulp::signal` and
  `Pulp::midi`, and never `Pulp::host`.
- `Pulp::view-core` no longer links `Pulp::audio` or `Pulp::signal`.
- Both view umbrellas link `Pulp::view-audio`.

Include paths are unchanged for both moves.

## Who is affected

- A DesignIR document whose manifest references a local file outside its own
  directory by absolute path — typically one written by code that calls the
  design-import library directly, or by hand. That asset no longer loads from
  the saved document. `pulp import-design`'s DesignIR, C++ and JS outputs copy
  external files into the output's `assets/` folder, and captured, packaged and
  network-fetched (cached) assets are not affected.
- Code that resolves assets without a document directory (an empty
  `asset_base_directory`) is unchanged.
- Code that uses `GraphEditorView` and reached it through `Pulp::host`: the
  link now fails with undefined `pulp::view::GraphEditorView` symbols.
- Code that links only `Pulp::view-core` and uses one of the audio widgets: the
  link, or the header lookup, now fails. Code that links the `Pulp::view` or
  `Pulp::view-native` umbrella is unaffected.

## Migration steps

1. Keep a document's assets inside its directory, or under its `assets/`
   folder, and reference them with relative paths.
2. For an external file, copy it into the document's `assets/` folder. When
   the manifest entry declares the file's SHA-256 in `content_hash`, a copy
   under `assets/` with the recorded file name is found automatically even
   though the recorded absolute path is refused.
3. Link `Pulp::view-graph-editor` wherever you construct or reference
   `GraphEditorView`. Keep `Pulp::host` only if the target also uses host APIs
   directly.
4. Where a target links `Pulp::view-core` directly and uses an audio widget,
   add `Pulp::view-audio`, or link the `Pulp::view` umbrella instead:

   ```cmake
   target_link_libraries(MyHostApp PRIVATE Pulp::view Pulp::view-graph-editor)
   target_link_libraries(MyMeterTool PRIVATE Pulp::view-core Pulp::view-audio)
   ```
