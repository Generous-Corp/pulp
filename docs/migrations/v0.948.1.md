## What changed

`GraphEditorView` (`<pulp/view/widgets/graph_editor_view.hpp>`), which draws
and edits a host `SignalGraph`, moved out of `Pulp::host` into a new
`Pulp::view-graph-editor` target, which links `Pulp::view-core` and
`Pulp::host`.
- `Pulp::host` no longer depends on `Pulp::view-core`.
- Neither view umbrella (`Pulp::view`, `Pulp::view-native`) links
  `Pulp::view-graph-editor`, so an ordinary view or plug-in UI does not pull in
  the plug-in host stack.
- The target is not built on iOS, where `Pulp::host` is absent. The header still
  installs.

The audio-dependent widgets moved out of `Pulp::view-core` into a new
`Pulp::view-audio` target: the meters, the waveform and spectrum visualizers,
the EQ curve, the audio inspector, MIDI binding, the plug-in manager panel and
the waveform GPU helpers.
- `Pulp::view-audio` links `Pulp::view-core`, `Pulp::audio`, `Pulp::signal` and
  `Pulp::midi`, and never `Pulp::host`.
- `Pulp::view-core` no longer links `Pulp::audio` or `Pulp::signal`.
- Both view umbrellas link `Pulp::view-audio`.

Include paths are unchanged for both moves.

## Who is affected

- Code that uses `GraphEditorView` and reached it through `Pulp::host`: the
  link now fails with undefined `pulp::view::GraphEditorView` symbols.
- Code that links only `Pulp::view-core` and uses one of the audio widgets: the
  link, or the header lookup, now fails. Code that links the `Pulp::view` or
  `Pulp::view-native` umbrella is unaffected.

## Migration steps

1. Link `Pulp::view-graph-editor` wherever you construct or reference
   `GraphEditorView`. Keep `Pulp::host` only if the target also uses host APIs
   directly.
2. Where a target links `Pulp::view-core` directly and uses an audio widget,
   add `Pulp::view-audio`, or link the `Pulp::view` umbrella instead:

   ```cmake
   target_link_libraries(MyHostApp PRIVATE Pulp::view Pulp::view-graph-editor)
   target_link_libraries(MyMeterTool PRIVATE Pulp::view-core Pulp::view-audio)
   ```
