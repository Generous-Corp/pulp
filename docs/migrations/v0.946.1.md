## What changed

When a DesignIR document is loaded from disk, its manifest assets resolve
relative to the document's own directory. An asset `local_path` or `file://`
`original_uri` that leaves that directory is now refused, whether or not the
file exists: a `../` segment (backslashes count as separators), an absolute
path elsewhere on the host, a drive-letter or UNC root, or a symlinked
directory that points out. A matching `content_hash` does not admit such a
path, with one exception: an absolute path to a file inside Pulp's own asset
cache (`PULP_IMPORT_ASSET_CACHE`, else the per-user cache) loads when the file
hashes to the declared `content_hash`, so network assets the importer fetched
keep working. The refusal is logged:

```
design-import: asset 'logo' refused — local_path '/elsewhere/logo.png' resolves
outside the document directory '/project/design'
```

The asset then reads as unresolved, as a missing file does.

## Who is affected

- A document that references a local file outside its own directory, which
  `pulp import-design` records as an absolute path when the source design
  pointed at an external file. That asset no longer loads from the saved
  document. Captured, packaged and network-fetched (cached) assets are not
  affected.
- Code that resolves assets without a document directory (an empty
  `asset_base_directory`) is unchanged.

## Migration steps

1. Keep a document's assets inside its directory, or under its `assets/`
   folder, and reference them with relative paths.
2. For an external file, copy it into the document's `assets/` folder. When
   the manifest entry declares the file's SHA-256 in `content_hash`, a copy
   under `assets/` with the recorded file name is found automatically even
   though the recorded absolute path is refused.
