## What changed

Every macOS bundle `pulp_add_plugin()` builds (VST3, CLAP, AU, AUv3, AAX,
Standalone `.app`) carried three control files beside its binary in
`Contents/MacOS`:

- `<target>.inspector-capabilities.json`
- `<target>.<format>.control-shipping.json`
- `<target>.<format>.control-shipping-report.json`

Apple reserves `Contents/MacOS` for code. An ordinary, non `--deep` signature,
which is what `pulp ship sign` makes, failed with "code object is not signed at
all / In subcomponent: ….json", so `pulp ship sign` could not sign a Pulp
bundle. Only `build_combined_installer.sh` worked, because it moved the files
aside first.

They are now written to `Contents/Resources` (`Versions/A/Resources` for a
framework). Plain executables and iOS bundles keep them beside the binary. The
build deletes copies an older SDK left in `Contents/MacOS`. Pulp's own readers
(a standalone's control endpoint, `pulp inspect` audits) look in
`Contents/Resources` first and still read the old location, so older bundles
keep working. `build_combined_installer.sh` no longer moves the files: it
refuses, before signing, a bundle that still has them in `Contents/MacOS`.

## Migration steps

1. Rebuild your bundles before signing them; a rebuild moves the files.
2. If a script of yours reads these files, look in `<bundle>/Contents/Resources`
   first and fall back to `<bundle>/Contents/MacOS` for bundles built before
   this release. `pulp::inspect::control_sidecar_directories()` gives the order.
3. Remove any step that moved or deleted these files before signing; it is no
   longer needed.
