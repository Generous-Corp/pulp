## What changed

The platform plug-in editor hosts and everything that creates them moved out
of `Pulp::view-core` into `Pulp::view-tooling`:

| Moved | Header (path unchanged) | Now linked from |
|---|---|---|
| `PluginViewHost::create()`, `set_factory()`, `clear_factory()`, `has_factory()` | `<pulp/view/plugin_view_host.hpp>` | `Pulp::view-tooling` |
| `register_platform_plugin_view_host()` | `<pulp/view/plugin_view_host.hpp>` | `Pulp::view-tooling` |
| The macOS, iOS, Windows and Linux editor hosts | (platform sources) | `Pulp::view-tooling` |
| `PluginFrameRenderer`, `FrameGeometry`, `compute_frame_clip()`, `paint_plugin_scene()` | `<pulp/view/plugin_frame_renderer.hpp>` | `Pulp::view-tooling` |

`Pulp::view` and `Pulp::format-view` link `Pulp::view-tooling`, so every
plug-in, Standalone and `Pulp::view` consumer keeps all of these.
`Pulp::view-core`, `Pulp::view-script` and `Pulp::view-native` do not.

What stays in `Pulp::view-core`: the abstract `PluginViewHost` class in
`<pulp/view/plugin_view_host.hpp>` (a view tree's back-pointer to its host,
the damage and frame requests a view routes to it, its GPU-surface observer
and `NativeViewHost` registration), `FrameCostProbe`, and the default editor
background `kEditorHostClearRgb`. `kEditorHostClearR`, `kEditorHostClearG` and
`kEditorHostClearB` are now declared in `<pulp/view/plugin_view_host.hpp>`;
`<pulp/view/plugin_frame_renderer.hpp>` still reaches them through it.

## Who is affected

- A target that links only `Pulp::view-core`, `Pulp::view-script` or
  `Pulp::view-native` and calls `PluginViewHost::create()` or the factory
  functions, or uses `PluginFrameRenderer` and the frame helpers. It now fails
  to link with undefined symbols for them.
- A target that subclasses `PluginViewHost` itself (a custom or recording
  host) while linking only `Pulp::view-core`: no change.
- Plug-ins, Standalones and anything linking `Pulp::view` or
  `Pulp::format-view`: no change.

## Migration steps

1. Link `Pulp::view-tooling` (or `Pulp::view`) wherever you create a
   `PluginViewHost` or use the plug-in frame pipeline:

   ```cmake
   target_link_libraries(my_host PRIVATE Pulp::view-tooling)
   ```
