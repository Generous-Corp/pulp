## Breaking changes
- `ValueChannelSet`, the value sources (`ScalarSource`, `MeterSource`, `VectorSource`, `EventSource`),
  `HostParamSurface`, `HostActionSurface`, `StateStoreHostParamSurface`, `AudioBridge` and
  `VisualizationBridge` now live in namespace `pulp::dataplane`, in the UI-free `pulp::dataplane` and
  `pulp::dataplane-audio` targets. The `<pulp/view/...>` headers still compile and bring each name into
  `pulp::view` with a using-declaration, so `pulp::view::ValueChannelSet` is the same class.
- A forward declaration such as `namespace pulp::view { class ValueChannelSet; }` no longer compiles: it
  declares a second class that conflicts with the using-declaration.
- Under `PULP_BENCHMARK`, `VisualizationBridge::set_bench_counters(render::bench::PerfCounters*)` is
  replaced by `set_bench_sink(VisualizationBenchSink)`.

## Migration steps
- Replace forward declarations of these types in `pulp::view` with `#include <pulp/dataplane/fwd.hpp>`,
  or include the type's header.
- Benchmark harnesses: `bridge.set_bench_sink({&counters.audio_copy_total_us, &counters.triplebuffer_publish_total_us});`.
- Code that only links the editor data plane can link `pulp::dataplane` (or `pulp::dataplane-audio`) instead
  of a view target.
