## What changed

`pulp::signal::OversamplerT` (`Oversampler`, `Oversampler64`) constructed
without `set_kind()` now filters with `Kind::polyphase_iir` instead of
`Kind::fir_biquad`. The polyphase lane is an elliptic half-band design
(`design_halfband_iir()`); `Quality::standard` is the default.

| | `fir_biquad` (old default) | `polyphase_iir` standard (new default) |
|---|---|---|
| Alias / image rejection | about 7-9 dB | 94.8 dB from 0.58 Fs |
| Passband | -1.8 dB at 0.3 Fs | flat (< 1e-8 dB) to 0.42 Fs |
| Cost per sample, x2 / x4 (M3 Ultra) | 15.2 / 27.9 ns | 2.6 / 7.2 ns |
| Round-trip delay near DC, x2 / x4 | 0.97 / 1.46 base samples | 2.66 / 3.49 base samples |
| Round-trip delay at 0.4 Fs, x2 | 1.5 base samples | 7.6 base samples |

Both lanes are minimum phase. `latency()` still reports a non-constant
delay and `latency_samples()` still returns 0, so host latency
compensation is unchanged; the extra delay is uncompensated.

The half-band classes (`HalfBandUpsampler2x`, `HalfBandDownsampler2x`)
also default to the new design: three sections per path instead of six,
rejecting 94.8 dB from 0.29 of their own rate.

## Who is affected

Only code that never calls `set_kind()`. You will hear a brighter top end
(the passband no longer droops) and less aliasing. Code that blends the
oversampled path with an unprocessed dry path, or aligns it against another
signal, sees the extra delay as comb filtering or a timing offset.

## Migration steps

To keep the previous sound and timing exactly, select the biquad lane:

```cpp
oversampler.set_kind(pulp::signal::Oversampler::Kind::fir_biquad);
```

To keep the new lane and align a dry path, read its delay from the filter
instead of hard-coding it:

```cpp
const double delay = oversampler.group_delay_samples(0.0); // base samples
```

`group_delay_samples(f)` is frequency dependent for both minimum-phase
lanes; use `Kind::linear_phase_fir` when a constant, host-compensated
latency is required.

Filter kinds, rejection, and delay curves are tabulated in
[Oversampling filters and the real-input FFT](../reference/oversampling-and-real-fft.md).
