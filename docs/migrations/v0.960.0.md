## What changed

Pulp's plug-in host and editor tooling moved out of `Pulp::view-core` and
`Pulp::view-script` into a new target, `Pulp::view-tooling`:

| Moved | Header (path unchanged) | Now linked from |
|---|---|---|
| `ViewInspector` | `<pulp/view/inspector.hpp>` | `Pulp::view-tooling` |
| `InspectorWindow` (layout inspector window) | `<pulp/view/inspector_window.hpp>` | `Pulp::view-tooling` |
| `EditorBridge` | `<pulp/view/editor_bridge.hpp>` | `Pulp::view-tooling` |
| `StateStoreHostParamSurface` | `<pulp/view/host_param_surface.hpp>` | `Pulp::view-tooling` |
| `ScriptInspectorBridge` | `<pulp/view/script_inspector_bridge.hpp>` | `Pulp::view-tooling` (JS builds) |
| `WaveformViewport` and the other waveform editor primitives | `<pulp/view/waveform_editor_primitives.hpp>` | `Pulp::view-audio` |

`Pulp::view` and `Pulp::format-view` link `Pulp::view-tooling`, so every plug-in,
Standalone and `Pulp::view` consumer keeps all of these. `Pulp::view-core`,
`Pulp::view-script` and `Pulp::view-native` do not.

What stays in `Pulp::view-core`:

- The abstract `HostParamSurface` and `HostActionSurface` contracts, now
  declared in `<pulp/view/host_surfaces.hpp>`. `<pulp/view/host_param_surface.hpp>`
  still includes it.
- `pulp::view::view_type_name(const View&)` in `<pulp/view/inspector_facts.hpp>`.
  It returns the same name `ViewInspector::type_name()` reports.

The runtime inspector is now opt-in. `ScriptedUiSession::script_inspector()` is
removed. A session carries a runtime-inspector port only when one was installed
before the session was constructed:

| Before | After |
|---|---|
| `session.script_inspector()` (never null) | `pulp::view::script_inspector(session)` (null when no bridge was installed) |
| always present | `pulp::view::install_script_inspector_bridge()` once, before building the UI |

Both functions are declared in `<pulp/view/script_inspector_bridge.hpp>`. A
Standalone built with the `dev.pulp.runtime/evaluate@1` control capability
installs the bridge automatically.

## Who is affected

- A target that links only `Pulp::view-core`, `Pulp::view-script` or
  `Pulp::view-native` and uses `ViewInspector`, `InspectorWindow`,
  `EditorBridge`, `StateStoreHostParamSurface` or `ScriptInspectorBridge`. It
  now fails to link with undefined symbols for those classes.
- A target that uses the waveform editor primitives while linking only
  `Pulp::view-core`. It now fails to link with undefined symbols for them.
- Code that calls `ScriptedUiSession::script_inspector()`. It no longer
  compiles.
- A host that wires its own runtime evaluator through the script-inspector
  bridge. Its sessions have no bridge unless it installs one first.
- Plug-ins, Standalones and anything linking `Pulp::view` or
  `Pulp::format-view`: no link change.

## Migration steps

1. Link `Pulp::view-tooling` (or `Pulp::view`) wherever you use the moved
   classes. Use `Pulp::view-audio` for the waveform editor primitives:

   ```cmake
   target_link_libraries(my_tool PRIVATE Pulp::view-tooling)
   ```

2. Replace `session.script_inspector()` with
   `pulp::view::script_inspector(session)`. Then call
   `pulp::view::install_script_inspector_bridge()` before constructing the
   sessions that must carry one, and handle a null result.

3. If you only needed a widget's type name, call `pulp::view::view_type_name()`
   from `Pulp::view-core` instead of `ViewInspector::type_name()`.
