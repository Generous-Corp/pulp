## Ladder saturator default

`LadderFilter::process()` now saturates each stage with
`FastMath::tanh_accurate` instead of `std::tanh`. The saturator is within
3.0e-7 of `std::tanh` for every float input when the compiler fuses
multiply-adds (Clang's default) and within 3.6e-7 when it does not (GCC under
Pulp's policy, MSVC, x86-64 without FMA). Against the exact-tanh ladder, over
cutoffs of 300 Hz to 6 kHz, resonance 0 to 1 and sine input of 110 Hz to
7 kHz at 48 kHz, the output differs by at most -124 dBFS for input up to
0 dBFS, -107 dBFS at +10 dBFS drive and -102 dBFS at +20 dBFS in either
contraction mode (measured with Apple clang and with GCC and glibc). Harmonic and alias levels and resonant ringing are
unchanged.

The saturator choice is now the `LadderSaturation` enum (`exact`, `accurate`,
`realtime_efficient`), selected at build time:

- `PULP_SIGNAL_LADDER_SATURATION` = `0` (exact), `1` (accurate) or
  `2` (realtime_efficient) selects it explicitly; any other value is a
  compile error.
- Otherwise `PULP_SIGNAL_FAST_LADDER_TANH` keeps its meaning when defined:
  `1` selects the Padé saturator and `0` selects exact `std::tanh`.
- With neither defined, the default is `accurate`.

`ladder_tanh_profiled<bool>` is deprecated in favour of
`ladder_tanh_profiled<LadderSaturation>`. The saturator itself is public as
`FastMath::tanh_accurate()`: odd, unit slope at 0, bounded, NaN-propagating
and branch-free.

## Compressor float conversions

`Compressor` (float) now converts detector level to dB and gain back to
linear with the branch-free `FastMath::gain_to_db_accurate()` and
`FastMath::db_to_gain_accurate()` instead of `std::log10` / `std::pow`, so its
block path vectorizes. They are within 4 ulps (log10) and 1.2e-7 relative
(10^x) of the correctly rounded result in either contraction mode, which keeps
the output within -120 dBFS of the previous libm path. Output is therefore
not bit-identical to earlier releases; `Compressor64` still uses libm. The
block and per-sample paths of one compressor remain bit-identical to each
other.

## Biquad block-path numerics

`Biquad::process(buffer, n)`, `SosCascade::process(buffer, n)` and the EQs
built on them (`ParametricEq`, `SixBandEq`, `GraphicEq` block processing) no
longer produce output bit-identical to looping the per-sample `process()`.
Each pass of up to sixteen sections picks one of three forms:

- float passes of up to four sections, including a single `Biquad`, run
  Direct Form I with double-precision state;
- longer passes, and every `Biquad64` pass, run a regrouped DF2T order when
  every pole radius is at most 0.995;
- otherwise the per-sample DF2T order, which stays bit-identical.

Over the RBJ design grid (eight filter types, 20 Hz to 15 kHz, Q 0.3 to 10,
±12 dB, 44.1/48/96 kHz, program and white-noise input; 2112 cases) the block
path's RMS error against an exact float64 filter is never more than the
per-sample path's, and on average 45 dB below it (47 dB without fused
multiply-add). Block and per-sample outputs therefore differ by the per-sample
path's own float round-off: at most -47.9 dBFS over that grid with fused
multiply-add and -44.7 dBFS without. The regrouped DF2T order stays within
+2.8 dB (RMS) of the per-sample path's error and differs from it by at most
-71 dBFS per section.

Switching between the per-sample and block paths on one filter is seamless:
the block path derives its state from the per-sample state and hands it back.

`Biquad` now carries the block path's double-precision history next to its
DF2T state, so the object is larger: `sizeof(Biquad)` grows from 28 to 72
bytes and its alignment from 4 to 8 (`Biquad64` from 56 to 104 bytes), as
measured with Apple clang on arm64. Code that relies on the old layout, such
as a fixed-size buffer, a binary-serialized struct or a static size check,
needs updating.

## TptFilter per-sample output

`TptFilter`'s state update is now `s + 2g (x - s)`, algebraically the
previous `lp + v`, so the recursion is one subtract and one multiply-add. The
per-sample outputs differ from earlier releases by float round-off; they are
not bit-identical.

## New voice banks

`LadderBank<Voices>` and `SvfBank<Voices>` (`ladder_bank.hpp`,
`svf_bank.hpp`, included by `signal.hpp`) run a fixed number of independent
`LadderFilter` / `Svf` voices in lockstep SIMD lanes. Each voice's output is
bit-identical to the scalar filter with the same settings; `process(in, out)`
advances every voice one sample and `process_voices(buffers, n)` a block.
`LadderBank` has one sample rate for all voices, applied immediately. This is
additive; existing code is unaffected.

## Migration steps

To keep bit-exact `std::tanh` ladder output, define
`PULP_SIGNAL_LADDER_SATURATION=0` (or `PULP_SIGNAL_FAST_LADDER_TANH=0`), or call
`LadderFilter::process_reference()` per sample or per buffer.

Replace `ladder_tanh_profiled<false>` with
`ladder_tanh_profiled<LadderSaturation::exact>` and `ladder_tanh_profiled<true>`
with `ladder_tanh_profiled<LadderSaturation::realtime_efficient>`.

Code that compared `Biquad`, `SosCascade` or EQ block output bit-for-bit
against a per-sample loop should compare within a tolerance, or call the
per-sample `process()` in its own loop.

Code that pinned `Compressor` (float) output bit-for-bit across releases
should compare within -120 dBFS, or use `Compressor64`.
