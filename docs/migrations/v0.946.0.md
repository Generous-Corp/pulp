## What changed

When a DesignIR document is loaded from disk, its manifest assets resolve
relative to the document's own directory. An asset `local_path` or `file://`
`original_uri` that leaves that directory is now refused, whether or not the
file exists and whatever `content_hash` the manifest declares. This covers a
`../` segment (backslashes count as separators), an absolute path elsewhere on
the host, a drive-letter or UNC root, and a symlinked directory that points
out. The refusal is logged:

```
design-import: asset 'logo' refused — local_path '/elsewhere/logo.png' resolves
outside the document directory '/project/design'
```

The asset then reads as unresolved, as a missing file does.

## Who is affected

- DesignIR documents whose manifest names an absolute path, or a path outside
  the document's directory. Documents written by `pulp import-design` keep
  their captured and packaged assets beside the document and are not affected;
  an asset the importer fetched over the network (opt-in) and recorded at its
  absolute asset-cache path no longer loads from a saved document and must be
  copied into the document's `assets/` folder.
- Code that resolves assets without a document directory (an empty
  `asset_base_directory`) is unchanged.

## Migration steps

1. Keep a document's assets inside its directory, or under its `assets/`
   folder, and reference them with relative paths.
2. If an asset lives elsewhere, copy it into the document's `assets/` folder.
   When the manifest entry declares the file's SHA-256 in `content_hash`, a
   copy named like the recorded path's file name under `assets/` is found
   automatically even if the recorded path is stale.
