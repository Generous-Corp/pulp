## What changed

The GPU device layer is now two targets below the 2D renderer:

- `Pulp::gpu-device-api`: an interface target over the Dawn-free device
  headers `pulp/render/gpu_surface.hpp`, `gpu_compute.hpp`,
  `gpu_diagnostics.hpp`, `gpu_startup_report.hpp`, `gpu_render_time.hpp` and
  `bench/perf_counters.hpp`.
- `Pulp::gpu-device`: the Dawn surface and compute implementation behind those
  headers.

`Pulp::render` links both, so a consumer of `Pulp::render` sees no change.
`Pulp::gpu-audio` now links `Pulp::gpu-device` instead of `Pulp::render`. No
header moved, and every `#include <pulp/render/...>` path is unchanged.

## Who is affected

A consumer that links only `Pulp::gpu-audio` and also uses the 2D renderer:
`pulp/render/skia_surface.hpp`, `headless_surface.hpp`, `render_loop.hpp`,
`renderer3d.hpp` or another renderer type. Before 0.946.0 those reached the
consumer through `Pulp::gpu-audio`'s link to `Pulp::render`. Now they fail to
link, with undefined symbols for the renderer types.

A consumer that uses only `GpuCompute`, `GpuSurface` or the other device
headers is not affected.

## Migration steps

Link the renderer explicitly where you use it:

```cmake
target_link_libraries(MyPlugin_Core PUBLIC pulp::gpu-audio)
if(TARGET pulp::render)
    target_link_libraries(MyPlugin_Core PUBLIC pulp::render)  # Skia 2D renderer
endif()
```

To reach the GPU compute primitives without the 2D renderer, link
`pulp::gpu-device` instead (it is present only in a GPU-enabled SDK build).
