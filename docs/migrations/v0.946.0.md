## What changed

When a DesignIR document is loaded from disk, its manifest assets resolve
relative to the document's own directory. An asset `local_path` or `file://`
`original_uri` that leaves that directory is now refused unless the file
hashes to the asset's declared `content_hash` (SHA-256). This covers a `../`
segment, an absolute path elsewhere on the host, and a symlinked directory
that points out. The refusal is logged:

```
design-import: asset 'logo' refused — local_path '/elsewhere/logo.png' resolves
outside the document directory '/project/design' and does not match a declared sha256
```

The asset then reads as unresolved, as a missing file does.

## Who is affected

- DesignIR documents whose manifest names an absolute path, or a path outside
  the document's directory, with no `content_hash`. Documents written by
  `pulp import-design` keep their assets beside the document and are not
  affected.
- Code that resolves assets without a document directory (an empty
  `asset_base_directory`) is unchanged.

## Migration steps

1. Keep a document's assets inside its directory, or under its `assets/`
   folder, and reference them with relative paths.
2. If an asset must live elsewhere, record its SHA-256 in the manifest
   entry's `content_hash`; the file then loads from its recorded path.
