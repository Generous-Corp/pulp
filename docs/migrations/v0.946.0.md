## What changed

`pulp::view::GraphEditorView` (`<pulp/view/widgets/graph_editor_view.hpp>`)
draws and edits a host `SignalGraph`. Until this release its implementation
was compiled into `pulp::host`, and `pulp::host` linked `pulp::view-core`. It
now lives in its own library, `pulp::view-graph-editor` (installed SDK:
`Pulp::view-graph-editor`), which links `pulp::view-core` and `pulp::host`.

- `pulp::host` no longer depends on `pulp::view-core`.
- None of the view umbrella targets (`pulp::view`, `pulp::view-native`)
  links `pulp::view-graph-editor`, so an ordinary view or plug-in UI does not
  pull in the plug-in host stack.
- The include path is unchanged.
- The target is not built on iOS, where `pulp::host` is absent. The header
  still installs.

A project that used `GraphEditorView` through `pulp::host` alone now fails to
link with undefined `pulp::view::GraphEditorView` symbols.

## Migration steps

1. Add `pulp::view-graph-editor` (installed SDK: `Pulp::view-graph-editor`) to
   the `target_link_libraries` of every target that constructs or references
   `GraphEditorView`.
2. Keep `pulp::host` if the target also uses host APIs directly. Otherwise it
   now arrives through `pulp::view-graph-editor`.

```cmake
target_link_libraries(MyHostApp PRIVATE pulp::view pulp::view-graph-editor)
```
