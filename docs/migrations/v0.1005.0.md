## What changed

`Processor` gains `virtual bool wants_sample_accurate_parameters() const`,
default `false`. In the VST3, AU v2 and CLAP adapters:

| | Default (`false`) | `true` (previous behavior) |
|---|---|---|
| `param_events()` | empty | every automation point, with its sample offset |
| Store value during `process()` | each automated parameter's last value in the block | the same |
| AU v2 scheduled automation | one `process()` call for the whole buffer | one call for the whole buffer, every point in `param_events()` at its buffer offset |
| Store writes per automated parameter | one | one (VST3, AU v2) or one per event (CLAP) |

A sample-accurate AU v2 processor used to be rendered once per slice between
scheduled events, with each slice's points relative to the slice and the
store at the slice's starting value. It now renders once per buffer, like
VST3 and CLAP, and the store holds the end-of-buffer value. A processor that
depends on the per-slice render can keep it by also overriding
`wants_au_scheduled_parameter_slices()` to return true.

Dense host automation (32 parameters at 16 points per 512-frame block) cost a
block-rate processor time per point, and on AU v2 one full render call per
slice. A processor that reads its parameters once per block now pays for
neither.

AU v3, LV2, AAX, the standalone and headless hosts, and graph nodes still
deliver every point regardless of the flag.

## Who is affected

A processor that reads `param_events()`, builds a `state::ParamCursor` over
it, or calls `for_each_subblock()`, and relies on intra-block automation
points. Without the override it now sees an empty event queue and block-rate
parameter values. A sample-accurate processor that read the store inside each
AU v2 slice instead of `param_events()` needs the second override.

## What to do

Override the flag in that processor:

```cpp
bool wants_sample_accurate_parameters() const override { return true; }
// Only if it reads the store per AU v2 slice instead of param_events():
bool wants_au_scheduled_parameter_slices() const override { return true; }
```

The adapters ask it once, when they create the processor. A processor that
reads parameters through `state().get_value()` once per block needs no change.
