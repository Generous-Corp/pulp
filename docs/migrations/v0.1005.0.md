## What changed

`Processor` gains two hooks. Both are appended to the vtable, and both
default to the behavior every processor already had:

- `virtual bool wants_sample_accurate_parameters() const`, default `true`.
- `virtual bool wants_au_scheduled_parameter_slices() const`, default `true`.

A processor that overrides neither sees no change: the VST3, AU v2 and CLAP
adapters deliver every automation point in `param_events()` with its sample
offset, and AU v2 renders one call per scheduled slice.

Two opt-outs make dense host automation cheaper:

| Override | VST3 and CLAP | AU v2 |
|---|---|---|
| `wants_sample_accurate_parameters()` returns `false` | `param_events()` is empty; each automated parameter's last value in the block is written to the store once, before `process()` | the same, and the whole buffer renders in one `process()` call |
| `wants_au_scheduled_parameter_slices()` returns `false` (sample-accurate kept) | no effect | the buffer renders in one call with every point in `param_events()` at its buffer offset, as VST3 and CLAP render it; the store holds the end-of-buffer value |

Measured on an Apple M5 Ultra with 32 parameters automated at 16 points per
512-frame block, an opted-out processor's automation cost falls from about
144 us to 1.4 us per block on AU v2, 22.8 us to 0.4 us on VST3 and 12.5 us to
2.0 us on CLAP.

AU v3, LV2, AAX, the standalone and headless hosts, and graph nodes deliver
every point regardless of either hook.

## Who is affected

No one has to change anything. A processor that reads its parameters once
per block through `state().get_value()`, and never reads `param_events()`,
builds a `state::ParamCursor`, or calls `for_each_subblock()`, can opt out
for the speedup. The examples and the `pulp create` templates now do.

## What to do

To opt a block-rate processor out:

```cpp
bool wants_sample_accurate_parameters() const override { return false; }
```

A sample-accurate processor that reads automation only through
`param_events()` (or a `ParamCursor` over it), and not the store inside each
AU v2 slice, can also render AU v2 buffers in one call:

```cpp
bool wants_au_scheduled_parameter_slices() const override { return false; }
```

The adapters ask both once, when they create the processor. Do not opt out a
processor that reads `param_events()`: its queue would be empty and its
parameters would move once per block.
