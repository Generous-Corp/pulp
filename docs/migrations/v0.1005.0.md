## What changed

`Compressor` and `Compressor64` (`CompressorT`) now smooth their gain
reduction with a decoupled peak detector by default: a peak hold that decays
at the release time, followed by an attack one-pole. Previously a single
one-pole switched between the attack and release coefficients (the
`branching` detector).

On a steady-level step nothing changes. `attack_ms` and `release_ms` are
still one-pole time constants, and a level step still moves from 10% to 90%
in about 2.2x the setting.

On tones and other periodic material the output changes. With the previous
detector the gain rode the waveform: attack measured about twice the knob,
the reduction settled short of the static curve, and the gain rippled at
twice the tone frequency. At threshold -20 dB, 4:1, hard knee, 5 / 100 ms and
a -6 dBFS tone:

| | decoupled (new default) | branching (previous) |
|---|---|---|
| 1 kHz attack, 10% to 90% (knob gives 11.0 ms) | 11.0 ms | 21.5 ms |
| Settled reduction (static curve -10.50 dB) | -10.49 dB | -9.75 dB |
| THD+N at 50 / 100 / 1000 Hz | -48.8 / -60.3 / -99.8 dB | -39.5 / -45.5 / -65.5 dB |

Products built on `Compressor`, including the Forge lo-fi, sidechain and
multiband compressor nodes, sound accordingly: cleaner on bass and sustained
tones, with attack that matches its setting.

## Migration steps

To keep the previous sound bit for bit, select the previous detector once
after construction:

```cpp
compressor.set_ballistics(pulp::signal::CompressorBallistics::branching);
```

Code that pinned `Compressor` output on tonal input in a fixture should
regenerate the fixture or select `branching`.
