## What changed

`Meter`, `WaveformView` and `SpectrumView` are implemented and declared by
`pulp::view-audio`. View-core, the design importer and the script bridge no
longer name them; they reach level, series and bin displays through three
view-core interfaces in `<pulp/view/data_display.hpp>`:

- `LevelDisplay` (`set_levels`, `set_level_orientation`, `set_level_fill`,
  `clear_level_fill`, `set_level_bar_ratio`, `set_level_render_style`)
- `SeriesDisplay` (`set_series`, `set_series_preview`)
- `BinDisplay` (`set_bins`)

Displays are created by id through `make_data_display("pulp.level" |
"pulp.series" | "pulp.bins")`. `pulp::view-audio` registers those ids from
`register_audio_widgets()` (`<pulp/view/register_audio_widgets.hpp>`).

## What you need to do

- **Plug-ins built with `pulp_add_plugin`, and the standalone host:** nothing.
  Editor creation and the standalone host register the displays.
- **Applications that link the view targets directly** and do not use
  `pulp_add_plugin` or the standalone host call
  `pulp::view::register_audio_widgets()` once at startup. Without it an
  imported meter, waveform or spectrum is a placeholder with a
  `data-display-unavailable` import diagnostic, and the bridge's
  `createMeter`, `createWaveform` and `createSpectrum` raise a script error.
- **Code that names `Meter`, `WaveformView` or `SpectrumView`** still compiles
  through `<pulp/view/widgets.hpp>` when it links `pulp::view` or
  `pulp::view-audio`. Code that links only `pulp::view-core` must use the
  interfaces above.
- **`NativeImportBindingContext` overrides:** `bind_meter` and
  `bind_waveform_display` are deprecated in favour of `bind_level_display` and
  `bind_series_display`. An override of only the old virtuals keeps working
  when `pulp::view-audio` is linked. A context that overrides both is called
  through both, so drop the old override when you add the new one.
- **Generated C++ from the design importer** now constructs displays with
  `make_data_display` and configures them through the interfaces. Regenerate
  checked-in generated sources to pick this up; previously generated code that
  names the concrete classes keeps compiling through `pulp::view`.

The classes gain bases and virtuals, so their layout and vtables change.
Pulp ships static libraries, so rebuild plug-ins against this SDK.
