## What changed

The design-import subsystem is now its own link targets instead of living
inside `pulp-view-core`:

- `Pulp::design-ir` — header-only DesignIR value types (`design_ir.hpp`,
  `design_source_types.hpp`). `Pulp::view-core` links it, so nothing changes
  for code that only carries IR values.
- `Pulp::design-import` — the importers and codegen: DESIGN.md parse/lint/diff,
  Figma/Stitch/v0/Pencil/Claude parsers, `design_ir_io.hpp`
  (`serialize_design_ir`, `parse_design_ir_json`, asset collection), codegen,
  lock-to-source. Exported only when the SDK is built with
  `PULP_ENABLE_DESIGN_IMPORT=ON` (the default).
- `Pulp::design-import-audio-pack` — the built-in Pulp Figma Library of audio
  controls for the recognition resolver.

`RecognitionResolver::with_builtin_library()` is replaced by the free function
`recognition_resolver_with_builtin_library()` in
`<pulp/view/recognition_audio_pack.hpp>`.

## Who is affected

- Consumers that link the umbrella `Pulp::view` (or `Pulp::view-native`, or a
  plugin made with `pulp_add_plugin`): **no change**. Both umbrellas link all
  three new targets.
- Consumers that link **only** `Pulp::view-core` and call an importer or the IR
  JSON round-trip: the link now fails with undefined `pulp::view::parse_*` /
  `serialize_design_ir` symbols.
- Code that calls `RecognitionResolver::with_builtin_library()`.

## Migration steps

1. If you link `Pulp::view-core` directly and use any design-import API, add
   `Pulp::design-import`:

   ```cmake
   target_link_libraries(my_tool PRIVATE Pulp::view-core Pulp::design-import)
   ```

   Linking `Pulp::view` instead also works.
2. Replace `RecognitionResolver::with_builtin_library()` with
   `recognition_resolver_with_builtin_library()` and include
   `<pulp/view/recognition_audio_pack.hpp>` (link
   `Pulp::design-import-audio-pack`, or `Pulp::view`).
