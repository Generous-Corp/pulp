## What changed

The installed-content registry (`ContentRegistry`, content-pack install and
preview, the capability-manifest parser) moved out of `Pulp::state` into a new
`Pulp::content` target. `#include <pulp/state/content_registry.hpp>` keeps
working. `ContentCapabilityManifest` itself is now declared in
`<pulp/state/content_capability_manifest.hpp>` and stays in `Pulp::state`.

`PresetManager` no longer reads content packs itself. It lists installed
content-pack presets only after a content-preset source is installed:

```cpp
#include <pulp/state/content_registry.hpp>

preset_manager.set_content_preset_source(pulp::state::content_registry_preset_source());
preset_manager.set_content_manifest(manifest);  // or set_content_plugin_id(...)
```

The CLAP adapter and the AU factory-preset table install the source on the
`PresetManager` they own, so plugins built with `pulp_add_plugin` are unchanged.

`GraphEditorView` (`<pulp/view/widgets/graph_editor_view.hpp>`), which draws
and edits a host `SignalGraph`, moved out of `Pulp::host` into a new
`Pulp::view-graph-editor` target, which links `Pulp::view-core` and
`Pulp::host`.
- `Pulp::host` no longer depends on `Pulp::view-core`.
- Neither view umbrella (`Pulp::view`, `Pulp::view-native`) links
  `Pulp::view-graph-editor`, so an ordinary view or plug-in UI does not pull in
  the plug-in host stack.
- The target is not built on iOS, where `Pulp::host` is absent. The header still
  installs.

The audio-dependent widgets moved out of `Pulp::view-core` into a new
`Pulp::view-audio` target: the meters, the waveform and spectrum visualizers,
the EQ curve, the audio inspector, MIDI binding, the plug-in manager panel and
the waveform GPU helpers.
- `Pulp::view-audio` links `Pulp::view-core`, `Pulp::audio`, `Pulp::signal` and
  `Pulp::midi`, and never `Pulp::host`.
- `Pulp::view-core` no longer links `Pulp::audio` or `Pulp::signal`.
- Both view umbrellas link `Pulp::view-audio`.

Include paths are unchanged for both moves.

## Who is affected

- Code that constructs its own `PresetManager` and opts into content-pack
  presets (`set_content_manifest()` / `set_content_plugin_id()`): without the
  call above, `content_presets()` and `all_presets()` no longer include
  content-pack presets.
- Code that uses `ContentRegistry` or the content-pack install/preview API and
  links only `Pulp::state`: the link now fails with undefined
  `pulp::state::ContentRegistry` symbols.

- WebAssembly plugins (WAMv2, WebCLAP) are unaffected: their preset manager
  never listed content-pack presets, and neither lane compiles the registry.
- Code that uses `GraphEditorView` and reached it through `Pulp::host`: the
  link now fails with undefined `pulp::view::GraphEditorView` symbols.
- Code that links only `Pulp::view-core` and uses one of the audio widgets: the
  link, or the header lookup, now fails. Code that links the `Pulp::view` or
  `Pulp::view-native` umbrella is unaffected.

## Migration steps

1. Where you opt a `PresetManager` into content packs, also call
   `set_content_preset_source(pulp::state::content_registry_preset_source())`.
2. Link `Pulp::content` wherever you use the registry, the source, or the
   content-pack install/preview API:

   ```cmake
   target_link_libraries(my_target PRIVATE Pulp::state Pulp::content)
   ```
3. Link `Pulp::view-graph-editor` wherever you construct or reference
   `GraphEditorView`. Keep `Pulp::host` only if the target also uses host APIs
   directly.
4. Where a target links `Pulp::view-core` directly and uses an audio widget,
   add `Pulp::view-audio`, or link the `Pulp::view` umbrella instead:

   ```cmake
   target_link_libraries(MyHostApp PRIVATE Pulp::view Pulp::view-graph-editor)
   target_link_libraries(MyMeterTool PRIVATE Pulp::view-core Pulp::view-audio)
   ```
