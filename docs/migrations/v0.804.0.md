## What changed

`pulp::view::VisualizationBridge::process()` no longer performs FFT or
waveform analysis and no longer publishes those snapshots. The audio callback
now performs only bounded, allocation-free metering and capture into
preallocated storage.

Spectrum and waveform analysis has moved to the new `poll()` method. Existing
`read_spectrum()` and `read_waveform()` calls remain cheap snapshot reads, but
their values advance only after a consumer calls `poll()`.

## Migration steps

1. Choose exactly one non-audio-thread owner for visualization analysis,
   normally the editor's UI frame clock.
2. Call `bridge.poll()` from that owner at the desired visualization cadence.
3. After polling, call `read_spectrum()` and/or `read_waveform()` to read the
   latest published snapshots.

For example:

```cpp
void Editor::on_frame() {
    visualization_bridge_.poll();
    const auto spectrum = visualization_bridge_.read_spectrum();
    // Publish spectrum to the editor.
}
```

Do not call `poll()` from the audio callback, and do not assign multiple poll
owners. `configure()` and `reset()` also remain quiescent control-thread
operations: stop audio production and polling before changing bridge
configuration or resetting its continuity state.

The bridge reports overflow, missing-channel, and topology discontinuities by
resetting analysis continuity and advancing the snapshot epoch, so consumers
should treat `(epoch, sequence_number)` as the identity of an analyzed frame.
