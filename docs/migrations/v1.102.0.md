## Deprecations
- The three-argument `interpret_wav_format(fmt_payload, data_size,
  fact_sample_count)` is `[[deprecated]]`. The fact chunk's sample count never
  changed the result; call the two-argument form.
- `WavFormatFacts::total_frames` is deprecated in its documentation in favour
  of `WaveDecision::recoverable_frames` from `decide_wave`. It still holds the
  whole frames of the `data_size` passed to `interpret_wav_format`; the
  decision, and `AudioFileInfo` (`num_frames`, `declared_frames`,
  `truncated`), also account for bytes the file does not hold.

## Migration steps
- Drop the third argument from any `interpret_wav_format` call. A caller that
  must refuse a truncated WAV sets `WavDecodeLimits::refuse_truncated` or
  checks an inspection with `wav_decode_admits`.

## Behavior changes
- `MemoryMappedAudioReader` reads WAV through the same decoder as
  `FormatRegistry::read`, `AudioReader` and `decode_wav`, so its integer samples
  now match theirs bit for bit. Each integer sample code is divided by
  2^(bits-1) instead of 2^(bits-1) - 1. Every value moves toward zero by a
  factor of (2^(bits-1) - 1) / 2^(bits-1): about 0.8% for 8-bit, about 0.003%
  (1/32768) for 16-bit, and less than 1.2e-7 relative for 24- and 32-bit.
  Positive full scale now reads just under 1.0 (32767/32768 for 16-bit), and
  negative full scale reads exactly -1.0. Float WAV samples do not change.
- The memory-mapped reader also applies the shared WAV acceptance policy. A WAV
  whose header declares more frames than it holds opens with the frames present,
  and `info().truncated` is set. A header that contradicts itself is refused.

## Migration steps
- No code change is needed. A test that compares memory-mapped WAV output
  against hard-coded values scaled by 2^(bits-1) - 1 needs its expectations
  updated, or a tolerance of one integer step.
