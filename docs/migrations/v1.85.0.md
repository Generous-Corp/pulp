## What changed
- `StateTree::begin_transaction()` returns a move-only `Transaction`. Edits
  apply at once; coalesced listeners get one burst on commit, and `abort()`
  reverts. `begin_transaction(UndoManager*, name)` records the transaction as
  one undo step. `begin_validated_transaction()` returns edits as
  `TreeEditResult` values.
- New: `move_child`, `remove_all_children`, `index_of`, `for_each_descendant`,
  `find_descendant`, `is_equivalent_to`, the `*_checked` edit methods, and
  `child_moved` / `parent_changed` / `ancestor_changed` listeners.
- Every `add_*_listener` takes an optional `ListenerDelivery`. The default,
  `kCoalesced`, behaves exactly as before outside a transaction.
- `StateTreeSynchroniser` emits a new `SyncDeltaType::ChildMove` delta for
  reorders made with `move_child`.

## Behavior changes
- When `add_child()` or `insert_child()` moves a node that already has a
  parent, the old parent's `child_removed` listeners now run after the node is
  attached to its new parent. Before, they ran in between. Listeners that read
  `child.parent()` in that callback now see the new parent.
- `clone_synced()` now unhooks a removed subtree's wiring, so re-adding the
  same subtree no longer leaves a duplicate set of listeners on it.

## Migration steps
- No changes are needed for existing callers.
- A listener that must see every individual edit inside a transaction should
  pass `ListenerDelivery::kImmediate` when it registers.
- A receiver of `StateTreeSynchroniser` deltas built against an older Pulp
  stops decoding at a `ChildMove` delta. Update both ends together.

## What changed
- `pulp/platform/special_dir.hpp` adds `special_dir(SpecialDir)` for the user's
  home, documents, application data, config, cache, logs, temp, bundle resources
  and preset folders on every platform.
- Application settings, `PresetManager`, `ContentRegistry` and the view layer's
  persisted stores now resolve their roots through it.

## Migration steps
- Code that duplicated these lookups can call `special_dir` instead.
- On Linux the settings and preset roots now ignore a relative `XDG_CONFIG_HOME`,
  and `ApplicationProperties` honours an absolute `XDG_CONFIG_HOME` instead of
  always using `~/.config`. Other locations are unchanged.
- On Android the content root now lives under the app files directory instead of
  the working directory.

## What changed
- `pulp/runtime/cancel.hpp` adds `CancelSource` (move-only owner that cancels on
  destruction), `CancelToken` (copyable observer) and `CancelRegistration`.
- `CancelToken::is_cancelled()` is lock-free and allocation-free, so it can be
  polled from the audio thread. `wait_for_cancellation(timeout)` and
  `register_callback(fn)` are for non-realtime threads.
- `AsyncStream`, `BackgroundJobContext`, `download_file`, `ModelStore` and
  `SearchIndex` now take or hand out `CancelToken`.

## Migration steps
- `CancellationToken` still exists and still converts to `CancelToken`, so
  existing callers compile unchanged. Prefer holding a `CancelSource` and
  passing its `token()`.
- `AsyncStream::cancellation_token()` and `BackgroundJobContext::cancellation_token()`
  now return `CancelToken`. Code that called `cancel()` on the returned value
  must keep its own `CancelSource` (or `CancellationToken`) instead.
- Include `<pulp/runtime/cancel.hpp>`. `background_job.hpp` no longer pulls in
  `async_stream.hpp`.

## What changed
- `pulp/runtime/fixed_function.hpp` adds `FixedFunction<Signature, Capacity>`, a move-only
  callable with inline storage and compile-time size checks.
- `format::BackgroundTaskLane::start` has a new overload taking a `HandlerFunction`
  (a `FixedFunction`), so a capturing lambda replaces the `void*` context.

## Migration steps
- None required. `start(handler, context, policy)` with a function pointer still works.
- The lane no longer exposes its stored handler or context members; they were private.

## What changed
- `set_log_sink` receives `(level, category, message)` for every record, in addition
  to the platform log and stderr.
- `FileLogSink` (size-rotated, owner-only, refuses symlinked or group/world-writable
  targets), `CaptureLogSink` and `ScopedLogSink` live in `pulp/runtime/log_sink.hpp`.
- `log_with_category` tags a record with a subsystem name. Existing helpers use the
  category `pulp`.

## Migration steps
- None required. Existing `log_info`, `log_warn` and `log_error` calls behave as before.
- Do not call any of the log functions from the audio thread; they allocate and lock.
