## What changed
- `FormatRegistry::read(path)` now applies default `DecodeLimits` (2^30 frames, 64 channels, 4 GiB of float output). Every built-in reader (WAV, AIFF, FLAC, MP3, OGG, CoreAudio) checks the header claim before allocating and decodes in bounded chunks; a file whose claim exceeds the limits returns `nullopt` with a logged reason instead of allocating from the header.
- `FormatRegistry::read(path, limits)` takes explicit ceilings; a zero field means no limit, and `DecodeLimits::unbounded()` disables all three. The in-tree callers that read a file the user or host chose (offline rendering, sample assets, impulse responses, memory-mapped fallbacks) pass `unbounded()`.

## Migration steps
- Code that reads untrusted audio (dropped files, downloaded content) can keep the default and treat `nullopt` as a refused file.
- Code that must read arbitrarily long material from a trusted path passes `DecodeLimits::unbounded()` or a larger explicit limit.
- Custom `FormatReader` subclasses may override `read(path, limits)`; the base implementation forwards to `read(path)` without applying limits.

## Breaking changes
- `storageGetItem` / `storageSetItem` / `storageRemoveItem` (and the `localStorage` shim) store entries under the per-user settings root, namespaced by the bridge's script base directory, with the key hashed. Entries previously written to `$TMPDIR/pulp-storage` are not migrated, and two plugins no longer share one store.
- `saveStylePreset` / `loadStylePreset` move from `$TMPDIR/pulp-style-presets` to the same per-user store.
- Preset names and folders passed to `PresetManager::save` / `rename` may no longer contain `..`, an empty component, or a Windows separator; nested folders such as `Keys/Analog` still work.

## Migration steps
- Treat values that lived in the temp directory as ephemeral (the OS already purged them on reboot); nothing to migrate.
- A script that shared a store across plugins should persist shared state through the plugin's own state instead.

## Breaking changes
- An `InterprocessConnection` / `InterprocessConnectionServer` TCP endpoint whose `host` is empty now binds `127.0.0.1`. Only the literal `0.0.0.0` binds every interface. An application that relied on the old all-interfaces default to accept LAN peers stops accepting them.
- `NamedPipe::create_server` creates POSIX FIFOs with mode 0600 (was 0666), and `ChildProcessManager` places its pipes under a per-user 0700 directory. A peer must run as the same user.

## Migration steps
- To accept remote peers deliberately, set `host = "0.0.0.0"` on the endpoint.
- Cross-account helpers that used a FIFO need a different transport (a socket with explicit host, or a shared file protocol).
