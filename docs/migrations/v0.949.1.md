## What changed

On iOS (and the other shallow-bundle Apple platforms), Pulp wrote its bundle
records into a top-level `Resources/` directory:

- `pulp_add_plugin()` and `pulp_add_ios_auv3()` wrote `Resources/pulp-build-info.json`;
- a plug-in that declares content kinds also got `Resources/pulp.plugin-runtime.json`.

A shallow bundle must not contain a top-level `Resources/` directory. When it
does, `codesign` refuses to sign it ("bundle format unrecognized", or "code
object is not signed at all" for the JSON sidecars at the root). Xcode's
CodeSign step then failed, and the `.appex` could not be installed on a
simulator or device. Builds that turn signing off (`CODE_SIGNING_ALLOWED=NO`)
did not show it.

Both records now sit at the bundle root in a shallow bundle:

- `<bundle>/pulp-build-info.json`
- `<bundle>/pulp.plugin-runtime.json`

macOS bundles are unchanged (`Contents/Resources/`). When an existing iOS build
tree writes the record again, it deletes the old copies under `Resources/`, and
the directory itself once nothing else is left in it.

## Migration steps

1. If a tool reads either record from an installed iOS bundle, read it at the
   bundle root. For bundles built before this release, fall back to `Resources/`.
   `pulp validate`'s content-manifest check already looks in both places.
2. If an iOS build still fails code signing after this update, delete the built
   `.appex` and `.app` once. Something other than Pulp's records is still in
   their `Resources/` directory.

## macOS bundles: control sidecars move to `Contents/Resources`

Every macOS bundle `pulp_add_plugin()` builds (VST3, CLAP, AU, AUv3, AAX,
Standalone `.app`) carried three control files beside its binary in
`Contents/MacOS`:

- `<target>.inspector-capabilities.json`
- `<target>.<format>.control-shipping.json`
- `<target>.<format>.control-shipping-report.json`

Apple reserves `Contents/MacOS` for code. An ordinary, non `--deep` signature,
which is what `pulp ship sign` makes, failed with "code object is not signed at
all / In subcomponent: ….json", so `pulp ship sign` could not sign a Pulp
bundle. Only `build_combined_installer.sh` worked, because it moved the files
aside first.

They are now written to `Contents/Resources` (`Versions/A/Resources` for a
framework). Plain executables and iOS bundles keep them beside the binary. The
build deletes copies an older SDK left in `Contents/MacOS`. Pulp's own readers
(a standalone's control endpoint, `pulp inspect` audits) look in
`Contents/Resources` first and still read the old location, so older bundles
keep working. `build_combined_installer.sh` no longer moves the files: it
refuses, before signing, a bundle that still has them in `Contents/MacOS`.

### Migration steps

1. Rebuild your bundles before signing them; a rebuild moves the files.
2. If a script of yours reads these files, look in `<bundle>/Contents/Resources`
   first and fall back to `<bundle>/Contents/MacOS` for bundles built before
   this release. `pulp::inspect::control_sidecar_directories()` gives the order.
3. Remove any step that moved or deleted these files before signing; it is no
   longer needed.
