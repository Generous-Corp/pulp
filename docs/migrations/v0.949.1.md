## What changed

On iOS (and the other shallow-bundle Apple platforms), Pulp wrote its bundle
records into a top-level `Resources/` directory:

- `pulp_add_plugin()` and `pulp_add_ios_auv3()` wrote `Resources/pulp-build-info.json`;
- a plug-in that declares content kinds also got `Resources/pulp.plugin-runtime.json`.

A shallow bundle must not contain a top-level `Resources/` directory. When it
does, `codesign` refuses to sign it ("bundle format unrecognized", or "code
object is not signed at all" for the JSON sidecars at the root). Xcode's
CodeSign step then failed, and the `.appex` could not be installed on a
simulator or device. Builds that turn signing off (`CODE_SIGNING_ALLOWED=NO`)
did not show it.

Both records now sit at the bundle root in a shallow bundle:

- `<bundle>/pulp-build-info.json`
- `<bundle>/pulp.plugin-runtime.json`

macOS bundles are unchanged (`Contents/Resources/`). When an existing iOS build
tree writes the record again, it deletes the old copies under `Resources/`, and
the directory itself once nothing else is left in it.

## Migration steps

1. If a tool reads either record from an installed iOS bundle, read it at the
   bundle root. For bundles built before this release, fall back to `Resources/`.
   `pulp validate`'s content-manifest check already looks in both places.
2. If an iOS build still fails code signing after this update, delete the built
   `.appex` and `.app` once. Something other than Pulp's records is still in
   their `Resources/` directory.
