## What changed

`Quality::standard` in the `polyphase_iir` lane (the default oversampler)
uses a deeper elliptic half-band design: eight sections at stage 0 instead of
six, with the passband edge moved from 0.42 to 0.44 of the base rate.

| | Before | After |
|---|---|---|
| Alias / image rejection | 94.8 dB from 0.58 Fs | 113.3 dB from 0.56 Fs |
| Passband | flat (< 1e-8 dB) to 0.42 Fs | flat (< 1e-8 dB) to 0.44 Fs |
| Round-trip delay near DC, x2 / x4 | 2.66 / 3.49 base samples | 3.39 / 4.51 base samples |
| Round-trip delay at 0.4 Fs, x2 / x4 | 7.6 / 8.6 base samples | 9.9 / 11.2 base samples |
| Cost per sample | 1 | about 0.88 (the balanced four-and-four section split schedules better) |

The float build's stages also keep their state in double now, so a float
round trip adds only the rounding of its float samples (about -150 dB)
instead of -132 to -139 dB of accumulated section rounding.

The delay remains uncompensated: `latency()` still reports a non-constant
delay and `latency_samples()` still returns 0.

## Who is affected

Code that uses the default kind or selects `polyphase_iir` with
`Quality::standard`. Aliasing drops and the top of the band is flat further
up; the extra delay matters only where the oversampled path is mixed with or
aligned against another signal.

## Migration steps

Nothing is required. To align a dry path, read the delay from the filter
rather than hard-coding it:

```cpp
const double delay = oversampler.group_delay_samples(0.0); // base samples
```

For a constant, host-compensated latency use `Kind::linear_phase_fir`.
Filter figures for every kind are in
[Oversampling filters and the real-input FFT](../reference/oversampling-and-real-fft.md).
