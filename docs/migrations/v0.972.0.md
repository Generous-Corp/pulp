## What changed

`Pulp::state` now exposes only its own headers through its public include
directories. `<pulp/state/state.hpp>` no longer includes the content registry,
and consumers that use the installed-content API must include
`<pulp/state/content_registry.hpp>` explicitly.

The state target has never owned the content registry implementation. A
consumer that uses `ContentRegistry`, `content_registry_preset_source()` or
the content-pack install and preview API must link `Pulp::content` explicitly;
the state target no longer supplies that dependency through a transitive
include path.

## Migration steps

Add the content registry header and target where the API is used:

```cpp
#include <pulp/state/content_registry.hpp>
```

```cmake
target_link_libraries(my_target PRIVATE Pulp::state Pulp::content)
```
