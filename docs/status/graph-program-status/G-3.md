# G-3 authored graph identity

Status: **PARTIAL / EVIDENCE-GATED**

Wave 3 implements the post-G-1 authored-port identity surface in
`pulp/host/graph_identity.hpp`. It validates UTF-8 scalar names, rejects NUL,
control, empty, whitespace-only, and duplicate normalized names, applies the
one-hop versioned alias rule, and computes an order-independent semantic
fingerprint. The same value-owned surface reports added/removed names and
canonical-order changes and captures a caller-applied undo record.

The implementation is control-side only. Canonical port numbers, runtime
scheduling, instance pointers, host paths, telemetry, and machine-specific
execution choices are excluded. Fingerprints return zero for invalid records;
no lossy replacement string is emitted in diagnostics. NFC normalization uses
the complete Unicode 15.1 canonical decomposition, ordering, and composition
data (including Hangul), rather than a partial combining-mark table.

Executable planted controls are in `test/test_graph_identity.cpp`:

- `cutoff`, `drive`, and `mix` remain identical after reorder;
- declared `drive` → `Drive` alias resolves to authored `drive`;
- undeclared rename, duplicate names, whitespace-only name (including U+2003),
  C1 control characters, embedded NUL, invalid UTF-8, and decomposed-vs-composed
  Unicode controls outside the common Latin-1 table;
- value-owned undo capture and restoration.

The bounded D3 CLAP hosting slice is now implemented on the successor branch.
`pulp/host/plugin_identity.hpp` carries value-owned descriptor identity and
provenance; strict loading enumerates the requested descriptor, rejects
display-name or descriptor-zero fallback, verifies the initialized plugin's
own descriptor, and preserves loaded-versus-declared evidence through worker
and cache boundaries. The hermetic two-descriptor fixture and
`examples/clap-identity-consumer` provide the positive path and planted
refusals for missing, duplicate, invalid, incomplete, and mismatched IDs,
plus installed-header checks that reject public evidence forgery. The focused
CLAP suite passes 88 assertions in 4 cases, and the installed consumer builds
and runs against `Pulp::host`.

D3 remains bounded: it does not provide a hosted resolved-plan fingerprint,
portable release identity, cross-platform execution compatibility, plugin
containment, or runtime mutation lineage. D4 prepared-description export and
the broader semantic/execution receipt packet remain separate evidence-gated
work.

The broader graph semantic/execution receipt packet remains evidence-gated:
plugin identity portability, floating-point canonicalization, prepared-plan
fingerprints, cross-process receipts, and runtime mutation lineage still need a
separate owner and conformance lane. This slice does not make those claims.
