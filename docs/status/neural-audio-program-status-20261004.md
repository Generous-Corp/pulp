## Apple Silicon host serviceability (evidence-bounded)

These rows distinguish an experiment host that can run a lane from a host that has earned product support. A pass on one Apple Silicon variant never promotes another.

| Host | Current serviceability disposition | Evidence and limits | Required promotion gate |
|---|---|---|---|
| M1/M1 Max | CPU/reference lane and physical GPU correctness/fallback experiment | The two 60-second physical epochs in [`2026-09-27-gpu-audio-m1-duration.md`](https://github.com/danielraffel/pulp-planning/blob/main/research/2026-09-27-gpu-audio-m1-duration.md) matched the CPU oracle (max `1.825e-7`) through stop/restart/unload, with 445 non-priming CPU fallbacks out of 11,248 blocks. Dawn busy-service control was 286/734/1,117 us p50/p99/max, but it was post-submit and the host was loaded. This is not a GPU realtime or speedup claim. | Named model/provider and executable identity; 100,000 paced blocks at declared block/rate/channel/instance cells; exact per-block delivery and retirement counters; CPU shadow parity; GPU phase timestamps; reset/device-loss recovery; signed package identity. |
| M3/M3 Ultra | CPU/reference and parallel MLX/Dawn experiment host; no paced GPU qualification yet | Existing evidence is a focused causal-state test plus a post-submit Dawn control of 194/288/311 us p50/p99/max. The host audit recorded compilers/Spotlight and no reserved quiet run. These controls prove neither a persistent neural provider nor product performance. | Same host-bound named-model receipt, plus measured MLX/Dawn parallelism at production block sizes, instance-scaling cost, reset/device-loss recovery, and delivered-block deadline margin. |
| M5 Studio/Max | M5 Studio is the primary sustained GPU-audio experiment candidate; M5 Max loaded runs are contention controls | M5 Studio completed 100,000 paced 32-frame blocks at lead 8 with 100,000 GPU completions, zero fallback/misses/parity failures and max error `1.08033e-7`; this remains experimental (no multi-hour or hard-RT proof). A loaded M5 Max 100,000-block run selected only 9 GPU callbacks and 99,991 fallbacks, showing why host load and variant must remain in the receipt. | Repeat quiet-host and controlled-contention runs with provider timestamps, cold starts, signed package/model/license hashes, and no cross-host promotion. |

Current status is therefore CPU-first across all three host families once the CPU receipt is present; GPU/Dawn and MLX remain host-specific, opt-in experiments. No row authorizes a universal “Apple Silicon supported” or hard-realtime badge.

## Open product gates

1. Real MLX execution with a named licensed model, CPU shadow parity, provider identity, fallback/reset receipts, and signed/notarized packaging.
2. Authenticated Dawn provider depth and timing on Apple Silicon, including ordered delivery, late/device-loss recovery, and deadline margin.
3. A named licensed Magenta/Forge consumer with sustained pacing and a real consumer receipt.
4. Linux and Windows realtime execution receipts.
5. Competitive benchmark safety counters measured by the real provider, with paced delivery, independent-process cold starts, named serialized model/corpus hashes, and the remaining campaign controls.

The coordination goal remains active until these gates have landed with evidence or an explicit reviewed disposition. E126 capability-transaction ownership and GPU-NAM/Dawn source ownership remain unchanged.
