## Saved-identity writer slice — 2026-11-14

`GraphSerializer::to_saved_document` wraps the existing `to_json` payload in
the `pulp.graph.saved-identity.v6` envelope without changing the raw graph
format or its version semantics. The envelope records deterministic authored
node identities derived from existing node and registry fields, plus bindings
for every serialized node. `inspect_document` validates duplicate, unknown,
and dangling identity bindings with named refusals. `from_saved_document`
validates before loading and verifies that authored identities were restored.
Inspection's semantic digest excludes per-node editor layout, while canonical
document bytes retain it.

The existing public `undo_port_identity` spelling remains for compatibility
and is marked as a deprecated snapshot helper; new callers should use
`snapshot_port_identity`. Installed-consumer, cross-platform, realtime, and
full Processor/ControlIndex evidence remain outside this slice.

## Edit history and document diff (2026-11-14)

`pulp/host/graph_history.hpp` adds value-owned undo/redo for graph edits.
`GraphEditHistory` records each edit as two saved-identity v6 documents plus a
`snapshot_port_identity` of every node port qualified by the node's saved
identity, so a recorded state holds no pointer into a live graph. Undo and redo
refuse with `Diverged` when the live graph no longer matches the recorded state
(an edit made outside the history is never discarded). Before touching the live
graph they inspect the target document and trial-restore it into a scratch
graph that carries the live graph's custom node types; the trial must load,
restore every node's state, leave no node unresolved that is resolved in the
live graph, and reproduce the snapshot's qualified port fingerprint. A refusal
there leaves the live graph untouched (`graph_untouched`). Only then is the
live graph reloaded; if that load still fails, the pre-call document is
reloaded and `rolled_back` is set only when that rollback meets the same
faithfulness test against the pre-call state. Each step
reports the authored ports it added and removed. No-op edits are not recorded,
a new edit clears redo, and depth is bounded by capacity.

`diff_graph_documents` compares two saved documents by logical identity
without loading plugins: nodes, connections (keyed by identity and port index),
editor layout (reported, never semantic) and other top-level sections. Two
documents that differ only in NodeId numbering compare equal. `pulp graph diff
BEFORE AFTER [--json]` exposes it read-only with the typed graph codes `Ok`,
`InvalidDocument` (with the inspector `refusal` and `side`), `FileUnreadable`
and `ResourceLimit`. Tests: `test/test_graph_history.cpp` and the CLI rows in
`test/test_cli_graph_code_parity.cpp`.

Limits: the rollback after a failed restore uses the pre-call document
without editor layout; the MCP `pulp_graph` tool does not expose diff. This
does not claim installed-consumer, realtime or cross-platform evidence.

### Adversarial review fixes (2026-11-15)

An adversarial review of the merged history, serializer, and subgraph
persistence code found these defects; each fix has a test in
`test/test_graph_history.cpp` or `test/test_signal_graph_subgraph.cpp` that
fails without it.

- Undo or redo could empty the graph: the old path cleared the live graph
  before the target was known to load (for example any Processor graph undone
  without a `ProcessorRestoreRegistry`), and `rolled_back` reported only that
  the rollback document parsed. The trial restore and the faithful-rollback
  test above replace that. The cost is that every plugin and Processor factory
  the document names is instantiated twice on a successful step.
- A graph that already held an unresolved node could never be undone; the
  unresolved check is now relative to the live graph.
- Redo after undo refused with `Diverged` on any graph with a sample region
  and a NodeId gap. `sample_regions` NodeIds are now compared as the authored
  identities they bind, in the diff and in the divergence check.
- Every restore renumbers NodeIds densely. `GraphHistoryResult::node_ids` now
  maps each authored identity to its NodeId after the call.
- `from_saved_document` checked only that each identity existed somewhere; it
  now requires each identity to name the node its persisted id was restored
  as, through `LoadResult::persisted_node_ids`.
- `inspect_document` accepted duplicate, zero, out-of-range, and non-integer
  node ids that the loader refuses; it now refuses them as `node_id_invalid`,
  so `from_saved_document` refuses them before clearing the caller's graph.
- `diff_graph_documents` reported the inspector's raw-NodeId digest, so two
  equal documents could show different digests. `before_digest` and
  `after_digest` are now digests of the identity-keyed compared view.
  `GraphDocument::semantic_digest` is unchanged and remains NodeId-sensitive.
- A record that threw while being read was always blamed on the before
  document; the refusal now names the side.

Deferred, needing an owner decision:

- Node identities are not stable across ordinary edits. An identity is
  `node:<type>:<name>[:uid | :type@version]:<ordinal>` with the ordinal
  assigned in NodeId order, so deleting the first of two same-key nodes makes
  the diff (and history `port_changes`) attribute the survivor's changes to
  the deleted node, and a rename reads as remove plus add. The `:` delimiter
  is also ambiguous between a plugin name and unique id that contain `:`.
  Fixing either changes the identity spelling recorded in every saved
  document, so it needs a persisted authored node id or a versioned identity
  scheme; it is not changed here.
- `pulp graph diff` exits 0 whether or not the documents differ, and 1 for a
  refusal. Reserving an exit code for "documents differ" changes the CLI
  contract and is left for the CLI owner.
- The CLI `ResourceLimit` row (a document over the 64 MiB bound) has no test.

### Final review fixes: identity, saved documents and CLI rewrites (2026-11-15)

The final adversarial and code-quality reviews of this slice found these
defects. Each fix has a test that fails without it (checked by breaking the
fix with `tools/scripts/confirm_failure.sh`).

- `pulp graph save`, `fmt` and `canonicalize` loaded through `from_json` and
  wrote `to_json`, so they exited 0 while stripping the saved-identity envelope
  and every `subgraphs` record, and no CLI command could write a `pulp graph
  diff` input. An envelope input is now restored through
  `from_saved_document` and written with the new
  `GraphSerializer::to_saved_file`; `save --saved-identity` writes the envelope
  for a plain input; a document with `subgraphs` records is refused with
  `subgraph_records_unsupported` and left unchanged (the CLI has no templates).
  A diff refusal for a plain graph carries a `hint` naming the save flag.
  Test: `graph save and fmt keep the saved-identity envelope that diff reads`.
- `from_saved_document` returned `ok` after the tolerant loader skipped a
  dangling, out-of-range or refused connection, so undo and redo could report
  `Ok` with an edge lost. Every saved connection must now be restored; the one
  permitted omission is the existing partial-load rule for a parameter edge
  into an unresolved plugin placeholder with a valid source node and output
  port. A declared spectral edge is refused on this ordinary identity surface
  rather than silently restored as audio. `from_json` keeps its tolerant
  behaviour. Test: `GraphSerializer saved documents refuse a connection that
  does not restore`.
- Inspection was quadratic in the member count of one object (the parser's
  duplicate-key scan), so a 2 MB file took about 24 s. Inspection and
  `from_json` now refuse more than `max_object_members` (1024) members in one
  object or `max_document_members` (2^20) in total, before parsing, as
  `member_limit_exceeded`. Test: `GraphSerializer bounds object members before
  parsing`.
- The spectral reader claimed every document that failed to parse, so a
  malformed ordinary graph was reported as "invalid spectral graph JSON". It
  now claims only a parsed object that names spectral content, and `from_json`
  clears the destination only after the document parses, so malformed input
  leaves the caller's graph untouched. Test: `Malformed ordinary graphs keep
  the ordinary loader's error`.
- The G-10 status documents, the hosting skill and a spectral test comment
  still said spectral persistence was refused; they now describe the format-6
  subset, and `docs/guides/spectral-asset-replay.md` lists the save rules.

Deferred from this review (too large for a minimal fix, or an API decision):

- A spectral graph has no saved-identity envelope, so `GraphEditHistory` and
  `pulp graph diff` do not cover spectral graphs; history reports
  `CaptureFailed` with a detail about authored port names. Supporting it needs
  the spectral envelope to carry identities and bindings.

### Strict identity inspection and spectral save reasons (2026-11-16)

Two items deferred from the final review are now fixed.

- `inspect_document` rebuilds each node's authored identity from its saved
  record with the writer's rule (ordinals assigned in persisted node id
  order) and refuses, as `identity_binding_unknown`, a document whose
  identity strings name other nodes. `diff_graph_documents`, `pulp graph
  diff` and `from_saved_document` inherit the check, so a document that
  swaps the identities of two nodes of different types is refused before any
  graph is touched. The record rule matches the loader for every node kind:
  a `processor` record is a Plugin node with no unique id, a `plugin` record
  keeps `plugin.unique_id`, a `custom` record uses `custom.type_id` and
  `custom.version` (1 when absent; below 1 is refused, as the loader cannot
  restore it), an unknown type string is a custom node of that type id at
  version 1, and an unnamed custom record is refused (see below). The
  writer's identity now records a custom type version below 1 as 1, the
  value the node record carries. Tests: `saved document inspection rebuilds
  identities for every node kind`, `... refuses identities that name other
  nodes` and `... rebuilds identities the loader would assign` in
  `test/test_graph_history.cpp`.
- The spectral writer has an overload that returns the rule a graph breaks,
  and `to_file` / `to_saved_file` append it to `serialization_refused`
  (sample regions, node and connection bounds, unsupported node kinds, gain,
  missing spectral configuration, asset and retained budgets, non-finite
  layout, unsupported edge kinds, file size, and a reader refusal of the
  written document). A `SpectralAnalysis` node has its own reason (live
  analysis is not persisted). Test: `Spectral save refusals name the rule the
  graph breaks`.

Follow-ups from the second final review, in the same change:

- One identity key format. `identity_key` and `format_identity` in
  `graph_serializer.cpp` build every authored identity; the writer
  (`authored_node_identity`, from a live node) and inspection
  (`saved_record_identity_key`, from a record) only extract fields, so the two
  cannot drift. The every-kind round trip above is the guard.
- One serializer dispatch. A private `serialize` owns the spectral, plain and
  saved-identity branches; `to_json`, `to_saved_document` and the file writer
  all call it, and the reason-less spectral `write` overload is gone. The CLI
  recognises a spectral graph by the serializer's rule (a node with a
  spectral identity).
- A dropped node record is no longer silent. `LoadResult::unrestored_node_ids`
  lists the persisted ids of node records the load could not add (a second
  Control index input, a plugin record without plugin info).
  `from_saved_document` refuses such a document as `node_not_restored`, and
  `pulp graph save`, `fmt` and `canonicalize` refuse it as `InvalidDocument`
  with a `node_not_restored` message, so `--saved-identity` can no longer
  stamp an envelope on a graph that lost an isolated node. Tests: `GraphSerializer
  reports node records the load could not add` and `graph rewrites refuse a
  plain document that loses an isolated node`.

Three cases that passed inspection and were refused only after
`from_saved_document` had cleared the destination graph are now refused by
inspection, before the destination is touched:

- Node records out of ascending id order. The loader creates nodes and counts
  identity ordinals in array order, while identities are counted in persisted
  id order, so two same-key records listed in reverse restored under each
  other's identities. Inspection refuses such a document as
  `node_id_invalid`, and the saved-identity writer sorts its node records by
  id, so only a hand-edited document is affected. Test: `saved document
  restore binds each identity to its persisted node` (a populated destination
  survives the refusal) and `saved document writer lists node records in
  ascending id order`.
- An unnamed Processor record. The loader names it after the restored
  descriptor, which inspection cannot know, so inspection refuses it as
  `identity_binding_unknown` without running a restore factory. The writer
  never emits one: a Processor node added without a name takes its
  descriptor name, and descriptor validation refuses an empty one. Tests:
  `saved document inspection refuses an unnamed Processor record` and `saved
  document writer never records an unnamed Processor node`.
- An unnamed custom record. The loader names it after a registered type's
  `default_name` when the destination registers one, and after its type id
  otherwise, and registry-free inspection cannot tell which, so inspection
  refuses it as `identity_binding_unknown`. The writer never emits one: a
  custom node added without a name takes the `default_name` or the type id
  at creation. Tests: `saved document inspection refuses an unnamed custom
  record` (a populated destination that registers the type survives the
  refusal) and `saved document writer never records an unnamed custom node`.

Still open: `to_saved_subgraph_document` returns an empty string without a
reason. A malformed node record is reported as
`identity_binding_unknown`; a dedicated code changes the wire-visible refusal
name and is left for the serializer owner.
