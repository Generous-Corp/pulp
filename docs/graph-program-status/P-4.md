# P4: shared model/resource admission (two-consumer evidence)

Status: **HOLD**. Historical measurements cover two graph consumers, but do not
prove that the staged convolver delivered GPU work. The strengthened fixture
requires completed GPU readbacks before emitting two-GPU-consumer evidence;
that hardware run remains NOT CHECKED. A shared admission contract is not
admitted as SDK API, and no graph-wide GPU or neural scheduler follows.

Gate (from `docs/reference/2026-11-12-post-roadmap-audio-graph-capability-gaps.md`,
section P4): two independent consumers and a workload whose frame geometry and
latency are measured from each fixture, with device-loss, fallback,
allocation, and output-tolerance controls.

## Why P4 was speculative while GPU NAM exists

GPU NAM is a real consumer of Pulp's GPU WaveNet primitive
(`GpuWaveNetSession`, `GpuNeuralRealtimeNode`), but it lives in its own
repository as a plugin `Processor`. It is one consumer of one resource kind,
and it does not run inside a `SignalGraph` next to a second GPU consumer. The
capability-gap plan called P4 speculative because no two graph consumers shared
an admission policy, not because GPU NAM is hypothetical. This experiment adds
the second consumer and puts both in one graph.

## What was built

Test: `test/test_graph_gpu_resource_admission.cpp`
(`pulp-test-graph-gpu-resource-admission`, registered in
`test/cmake/core_runtime_canvas_signal_tests.cmake` behind
`TARGET pulp::gpu-device AND PULP_GPU_AUDIO_EXACT_PROVIDER_PROOF` inside a
`pulp_gpu_proof_begin()`/`pulp_gpu_proof_end()` block, `RESOURCE_LOCK pulp_gpu`).
It is gpu-proof hardware evidence: required CI never runs it, and it is
owner-run on a physical GPU with `-DPULP_GPU_AUDIO_EXACT_PROVIDER_PROOF=ON`
and `ctest -L gpu-proof`. The five device-free policy cases, tagged
`[device-free]`, are also built into
`pulp-test-graph-gpu-resource-admission-policy` on every macOS build with a GPU
device target and run in the ordinary test selection without the gpu-proof
label. No runtime or public API
changed.

Graph: `input -> neural.wavenet -> convolution.fir -> output`, both consumers
added with `SignalGraph::add_processor_node`. Each consumer stages host
callbacks into one fixed quantum and drives a `GpuAudioTransport`.

| Consumer | Node | GPU path on m3 | CPU fallback |
| --- | --- | --- | --- |
| `neural.wavenet` | `GpuNeuralRealtimeNode`, WaveNet family, built by public `make_gpu_neural_model` | Real Dawn `GpuWaveNetSession`, shared-memory path, provider self-reports `dawn` | Inline exact CPU shadow |
| `convolution.fir` | `GpuConvolver`, `ProviderPolicy::StagedOnly` | Real Dawn `GpuCompute`, staged path | Continuously primed CPU convolution |

The two node classes share no implementation beyond `GpuAudioNode` and the
transport, so they are independent consumers in the sense the gate asks for.

Admission manifest (test-local, schema `pulp.test.graph-resource-admission.v0`),
one uniquely named entry per consumer, matched by ID in either order:

- identity: SHA-256 of the exact weight or IR bytes handed to the node;
- provider claim: `AttestedDawn` or `Unattested`. `AttestedDawn` requires the
  authenticated provider identity the node's private realtime path establishes
  (`realtime_gpu_provider_identity`: provider `Dawn`, `authenticated`) and a
  status that agrees with it. The status provider alone is self-reported and
  never attests; a status that names Dawn without that identity is
  `Unattested`;
- residency: provider-shared memory or host-staged, checked against
  `capability_report().path`;
- payload budget (declared bytes) and latency budget (ms, checked against the
  prepared graph's per-node artifact latency);
- expected device-loss transition (`ProviderLost`) and required CPU fallback;
- output tolerance (max abs error against an independent CPU oracle).

## Measured results (m3, Apple M3 Ultra, macOS 27.2, Release `-O3 -DNDEBUG`)

Receipt: `docs/evidence/p4-two-consumer-admission-20261115/receipt.json`. This is
historical fixture evidence measured at test commit
`0987fec90892da410b95ed1f77578083ffe2342c`; it makes no current-head evidence
claim after the repair merge. It predates the GPU-execution requirement and
must not be used to qualify that requirement.

| Fixture | Quantum | Neural / conv node latency | Graph latency | Measured lag | Max abs error | Callback allocations |
| --- | --- | --- | --- | --- | --- | --- |
| 48 kHz, host block 64 | 64 / 64 (conv FFT 512) | 192 / 192 | 384 | 384 | 1.5e-7 | 0 |
| 44.1 kHz, host blocks 256, 37, 1, 200, 256, 18 | 256 / 256 (conv FFT 1024) | 768 / 768 | 1536 | 1536 | 1.8e-7 | 0 |
| 48 kHz, ragged 64, 21, 43, device loss mid-run | 64 | 192 / 192 | 384 | 384 (declared) | 1.3e-7 across the loss | 0 |

Latency is measured by lag search of the graph output against a zero-latency
CPU oracle that shares no node, transport or staging code; it matched the
graph's declared PDC exactly in both geometries. The neural consumer delivered
158 GPU blocks per healthy fixture with no fallback blocks.

Historical hardware controls reported 10/10 repeated runs on this host. Later
device-free policy controls are separate and do not establish hardware proof:

- **Device loss (fault-injected, not hardware):** the convolver's real Dawn
  device is put into the lost state with `GpuCompute::notify_device_lost`; the
  neural node latches `ProviderLost` through its private recovery seam (the
  reason the Dawn shared-I/O bridge raises on loss). Both consumers report
  `ProviderLost` / `Unavailable`, the neural fallback count rises from 0 to 80,
  the convolver reports the CPU engine, and the output stays within 1.3e-7 of
  the oracle with no silent quantum.
- **Fallback negative:** a neural consumer without a CPU shadow is refused by
  admission (`fallback-missing`); run anyway, the same loss produces silent
  quanta and fails the tolerance control.
- **Admission negatives:** identity drift, a Dawn claim for the staged
  convolver, a neural status that names Dawn with its authenticated identity
  removed or unauthenticated (false-provider control), a wrong residency claim, a 2 ms latency budget, a 64-byte payload
  budget, a consumer missing from the manifest, and a manifest entry with no
  consumer are each refused with their own error.
- **Tolerance negative:** a one-sample misalignment either way exceeds the
  1e-4 tolerance.
- **Non-finite negative (device-free):** an isolated NaN or Inf in the output
  or the reference breaks both tolerance helpers (`max_error_at`,
  `measure_lag`); a non-finite sample counts as an unbounded error, so
  corrupted audio cannot pass by being skipped in `std::max`.
- **Overlap bound (device-free):** both helpers compare only the samples
  where output and reference overlap at the given lag, so a reference
  shorter than the output is never read past its end, and a lag with no
  overlap is an unbounded error rather than a vacuous pass.
- **Allocation negative:** the allocation probe counts a planted allocation in
  the same binary.

## Strengthened admission and loss controls

Pre-render admission requires GPU kernel capability for both consumers and a
unique bijection between manifest entries and observations. Before geometry
evidence is emitted, and before injecting device loss, the convolver must have
positive `worker_output_blocks` **and** `staged_gpu_blocks()` (successful, finite
GPU readbacks). Worker output alone can include CPU convolution. The geometry
receipt now emits the staged GPU block count. The neural consumer must also
have positive GPU delivery.

Device-free controls reject a missing kernel, CPU-only worker output, duplicate
manifest IDs (appended or replacing another entry), and duplicate observation
IDs. Loss validation matches each observation by consumer ID and checks that
entry's transition. The serial graph's end-to-end error must satisfy every
entry's tolerance. Distinct transitions, reversed observations, and independent
mutations of either entry's transition or tolerance prove that neither entry
can be silently ignored. The strengthened hardware fixture has not been run.

## Findings the manifest surfaced

1. **Provider attestation is asymmetric.** The neural shared-memory path
   returns an authenticated Dawn provider identity; the staged convolver reports `Unknown` even on a live
   Dawn device, by design, because a staged device does not authenticate its
   provider or attribute blocks to an engine. A shared manifest therefore has to
   carry `Unattested` for one consumer. A graph-level policy such as "admit only
   attested GPU providers" would refuse the convolver today.
2. **Fallback delivery counters do not prove audio.** With no shadow, the
   transport still counts the block as `cpu_fallback_blocks`, and the node
   emits zeros. Admission must read `capability_report().fallback_available`,
   and continuity must be measured on the audio, not on the delivery counter.
3. **Latency is geometry-dependent and large at big blocks.** 1536 samples
   (34.8 ms) at 44.1 kHz / 256 for this two-node chain, because each consumer
   pays a two-block lead plus one staging quantum. A per-consumer latency budget
   is checkable from the prepared latency snapshot alone.

## What remains NOT CHECKED

- Real hardware or render-owner device loss; only the notification and
  recovery seams were injected.
- Device memory residency; the payload budget is declared bytes, not a
  measured device allocation.
- A current hardware run satisfying the staged GPU readback and worker-output
  requirements; the historical receipt has no staged GPU block counter.
- Per-block end-to-end GPU attribution for the staged convolver; its completed
  readback count is aggregate evidence, not a trace through the graph output.
- Warm-up and prewarm budgets, AutoReacquire recovery inside a graph.
- Deadline behavior under a live audio device callback; the render is an
  offline graph loop with a test-driven, non-realtime pump.
- A signed or serialized manifest; the manifest is test-local and processor
  nodes are refused by graph serialization.
- Installed-SDK consumer, Windows, Linux, and the GPU NAM plugin repository
  itself (this uses the same in-SDK WaveNet primitive, not the plugin).

## Recommendation: HOLD

The written gate asked for two independent consumers and a measured receipt
before any shared admission contract. Re-run the strengthened hardware fixture
before claiming two-GPU-consumer qualification. It is not admitted as SDK
API because (1) the provider claim cannot be uniform until the staged convolver
can attest its provider, or the manifest formally allows an unattested GPU
path; (2) device loss is fault-injected only; and (3) no live-callback deadline
or measured device-memory evidence exists. The next smallest experiments, in
order: run the same graph under a real device callback with the transport's own
worker; repeat the loss through a render-owner device loss; decide whether
`Unattested` is an acceptable admission state. Until then the manifest stays a
test fixture and no graph-wide GPU or neural scheduler is proposed.
