PR they list as open or unmerged (#11926, #11947, #11957, #11964 through #11971)

  named-bus (2/2) and tuning (3/3) cookbooks pass. The spatial cookbook
  failed its nested-macro proof: it expected the instantiated `inner.gain`

  `docs/guides/g11-live-retune-cookbook.md` (registered in
  `test/cmake/g11_live_retune_tests.cmake`) prove sample-timed retuning at
  two fixed boundaries on an offline host. Scope is narrow: no realtime
  callback, no device, no graph serialization. The earlier "sample-timed graph
  retuning unproven" lines are superseded only to that extent.
- **Named-bus recipe.** `examples/graph-named-bus-cookbook` is a
  `ProcessBuffers` harness driving one processor directly, not a `SignalGraph`.
  It does not check the baked-artifact boundary. Its planted-swap control now
  passes only on the marker `named-bus planted defect detected: swapped-names`.
- **Registrations.** The named-bus, spatial, and tuning cookbooks run through
  installed-SDK gates in `test/cmake/g11_cookbook_tests.cmake`, alongside the

  [test lanes](../guides/test-lanes.md)). The lane that runs them is the

The installed-SDK consumer in `examples/graph-named-bus-cookbook` declares a
mono `Source` input, stereo `Front` main output, and optional stereo `Rear`
aux output. It selects declared layouts through the public format API and
renders through named `ProcessBuffers` in a direct host-side harness. Positive
controls cover front-only and front-plus-rear layouts; planted swapped output
names and an undeclared layout are rejected.

The installed SDK consumer in `examples/graph-spatial-cookbook` uses G-4's
public bounded Input/Output/Gain subgraph template to route one mono input to
the two channels of a stereo output. Two declared gain paths carry independent
instance-local state. Its fixture renders a known impulse, checks both channels
and every silent frame, restores state, and confirms a planted swapped edge is
rejected by the same oracle.

Both recipes are fixed channel weighting. The named-bus recipe proves the
format processor contract, not named-bus integration in SignalGraph. G-4
exposed port names are graph handles; the Output node's port indices select
host channel positions. The static tuning recipe is documented in
`examples/g11-tuning-cookbook`. The live-sampling recipe is the installed-SDK
`sample-region-allpass` consumer described in
[`g11-live-sampling-cookbook`](../guides/g11-live-sampling-cookbook.md): it
declares a bounded sample-region graph with explicit `UnitDelay` causality,
renders regular and irregular callback schedules, reloads and bakes the graph,
and checks an independent scalar oracle. A current-head receipt against
`633825f7af3d4c8d0fee7e4ec139588282bdf0a1` reports six render paths and a
maximum oracle error of `6.503505523003383e-08`; planted negatives cover
changed graph contracts, tampered or untrusted signed bakes, legacy loader

[`g11-live-sampling-evidence-20261106`](../reports/g11-live-sampling-evidence-20261106.md)

[`docs/evidence/g11-live-sampling-current-head-20261106`](../evidence/g11-live-sampling-current-head-20261106/).

capability.

## Recording and atomic publication fixture

The new `examples/g11-recording-publication` consumer composes the installed
public SignalGraph, recorder, sample-slot publication, and loop playback
primitives. It captures a real graph input on the callback, stops at a bounded
frame count, publishes on the stopped control side with no callback file I/O,
and plays the captured immutable view through a second graph.

Its positive oracle covers regular and irregular block schedules, every sample
of the captured and played buffers, invalid preparation, idle command refusal,
reset, republication, and generation validity. Planted wrong-buffer,
timing-shift, and stale-publication controls each feed a real defect to the
unchanged oracle and pass only when it is rejected and the exact detection
marker is printed (`PASS_REGULAR_EXPRESSION`, not `WILL_FAIL`). The focused
registration is isolated in `test/cmake/g11_recording_publication_tests.cmake`.

This fixture is deterministic offline evidence. It does not claim device input,
realtime deadline qualification, graph serialization of processor-owned
recorder state, or a complete sampler product. The existing static
sample-region receipt remains separate and is not recording evidence.

The recording consumer's `--two-take` acceptance extends this boundary with
one prepared graph: it captures and publishes a 440 Hz take, holds and loops
voice A while recording an irregular 660 Hz take, publishes B as a new voice,
then releases and acknowledges A. Exact scalar oracles cover regular and
irregular partitions; slot exhaustion, stale generation, and idle-command
refusal remain explicit negatives. This is still deterministic offline
evidence and does not claim device, realtime, callback-I/O, serialization, or
cross-platform qualification.
