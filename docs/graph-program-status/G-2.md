## Graph-file reload (2026-11-13)

Delivers transactional whole-file reload for issue 12177 item 5:
`GraphFileReloadTransaction` and `GraphFileWatch` (`core/host/graph_file_reload`)
stage a `.pat` or `.pulpgraph` replacement through `PreparedTopologyEdit`, so an
invalid, unrepresentable, failed-prepare or stale document leaves the old graph
live. `SignalGraphControlAuthority::reload_graph_file` and the
`dev.pulp.graph/file.reload@1` control operation publish it; `pulp dev` and
`pulp loop` accept `--graph-file` and poll it through that operation. Processor
lifetimes are reserved process-wide so a retained snapshot cannot alias a
reloaded instance. Guide: `docs/guides/graph-file-reload.md`.

Remaining: Windows watch qualification (issue 12015), DSP-state migration into
fresh instances, opaque/custom state contracts, and SIGINT delivery while the
watch's build-lease heartbeat runs `system()` (the owned-heartbeat change was
left out of this slice). WakeSignal stays open under issue 12177.

The canonical `.pulpgraph` JSON notation is owned by `pulp::host::GraphSerializer`.
This slice adds `pulp graph inspect`, `pulp graph validate`, and
`pulp graph canonicalize`; all load with plugins disabled, preserving a safe,
metadata-only inspection path. The `pulp_graph` MCP tool delegates only the
read-only `inspect` and `validate` operations; `canonicalize` remains a CLI-only
write.

Acceptance: deterministic serializer round-trip remains covered by
`test_graph_serializer`; CLI/MCP wiring is exercised by the corresponding build
and tool-surface checks. Canonicalize writes to a same-directory temporary file
and replaces the destination only after the serialized output is complete.

Format v4 adds a bounded `processors` envelope. Each runtime-owned Processor
record carries its exact descriptor identity, channel shape, StateStore schema,
and separately encoded parameter/custom state. Emission is control-thread only;
the transactional `ProcessorRestoreRegistry::restore_batch` successor remains
the public installed-SDK restore path and returns no candidates on any failure.

The public `GraphSerializer::to_file` / `from_file` pair writes and reads a
bounded 64 MiB encoded
`.pulpgraph` envelope before invoking the JSON loader. Read, size, and
same-size concurrent-replacement failures return a diagnostic without clearing
the caller's existing graph. Save uses the durable file-replacement primitive,
refuses unresolved custom node types, and reports stable typed failure codes.
The CLI uses this same path for `inspect`, `validate`,
`explain`, `render`, `fmt`, `save`, and `canonicalize`; the installed G-2 consumer
reloads a v4 Processor graph from disk and checks the missing-file no-mutation
control. This is file reload and notation parity evidence, not plugin catalog
discovery or arbitrary path trust.

### Web consumer linkage repair — 2026-11-06

The isolated sample-region WAM/WebCLAP source closure now compiles
`core/runtime/src/durable_file_replacement.cpp` alongside
`core/host/src/graph_serializer.cpp`. This is required because the public
`GraphSerializer::to_file` path calls `DurableFileReplacement`; omitting the
runtime implementation leaves web consumers with unresolved link symbols.
The compatibility baseline test asserts both source-list entries and the
serializer's corresponding symbols. The WASI implementation now skips the
unsupported `fchown` ownership restoration while preserving mode bits, so the
same closure compiles under `wasm32-wasip1-threads`. This repair is carried on
the fresh successor branch `repair/g2-web-linkage-successor-20261106` in
[Generous-Corp/pulp#11722](https://github.com/Generous-Corp/pulp/pull/11722),
which remains unarmed pending the normal exact-head review and macOS gate.
The stale [Generous-Corp/pulp#11698](https://github.com/Generous-Corp/pulp/pull/11698)
remains untouched.
