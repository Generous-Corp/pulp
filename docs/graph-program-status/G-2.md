The canonical `.pulpgraph` JSON notation is owned by `pulp::host::GraphSerializer`.
This slice adds `pulp graph inspect`, `pulp graph validate`, and
`pulp graph canonicalize`; all load with plugins disabled, preserving a safe,
metadata-only inspection path. The `pulp_graph` MCP tool delegates only the
read-only `inspect` and `validate` operations; `canonicalize` remains a CLI-only
write.

Acceptance: deterministic serializer round-trip remains covered by
`test_graph_serializer`; CLI/MCP wiring is exercised by the corresponding build
and tool-surface checks. Canonicalize writes to a same-directory temporary file
and replaces the destination only after the serialized output is complete.

Format v4 adds a bounded `processors` envelope. Each runtime-owned Processor
record carries its exact descriptor identity, channel shape, StateStore schema,
and separately encoded parameter/custom state. Emission is control-thread only;
the transactional `ProcessorRestoreRegistry::restore_batch` successor remains
the public installed-SDK restore path and returns no candidates on any failure.

The public `GraphSerializer::to_file` / `from_file` pair writes and reads a
bounded 64 MiB encoded
`.pulpgraph` envelope before invoking the JSON loader. Read, size, and
same-size concurrent-replacement failures return a diagnostic without clearing
the caller's existing graph. Save uses the durable file-replacement primitive,
refuses unresolved custom node types, and reports stable typed failure codes.
The CLI uses this same path for `inspect`, `validate`,
`explain`, `render`, `fmt`, `save`, and `canonicalize`; the installed G-2 consumer
reloads a v4 Processor graph from disk and checks the missing-file no-mutation
control. This is file reload and notation parity evidence, not plugin catalog
discovery or arbitrary path trust.
