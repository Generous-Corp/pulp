## Authored subgraph persistence in the v6 document (2026-11-14)

`pulp/host/subgraph_persistence.hpp` persists authored `SubgraphInstance`
values through the saved-identity v6 document. `to_saved_subgraph_document`
writes the existing envelope plus a `subgraphs` record per instance: template
identity, instance identity and index, nested child template identities and
indices, member nodes named by their logical identities in expansion order,
and declared parameter values. No runtime NodeId enters a record. Parameter
values are read from the live graph (the target Gain node's gain or the target
Processor's `StateStore`), not from the instance's cached `parameters`, which
only `restore_subgraph_state` updates; an edit made through `set_node_gain` or
a Processor parameter is therefore saved, and a live value outside its
declared bounds is refused rather than written into a document that cannot
load. The writer refuses stale or foreign nodes, handles whose exposed ports no
longer match the live node's owner and incarnation (for example handles held
across an undo, redo, or reload, which renumber NodeIds), a node shared by two
instances, and duplicate instance identities.

`from_saved_subgraph_document` takes the caller's templates. Unknown or
duplicate templates and document inspection failures are refused before the
graph is touched, and those refusals leave the graph unchanged. After the
flattened graph loads, each record is checked
against a scratch expansion of its template: member count, node type and
nested name, child identities and indices, and the internal edge set must
match, and the declared parameter values go through `restore_subgraph_state`,
so bounds and Processor targets come from the template rather than the
document. Any mismatch clears the graph and returns no instances. Restored
instances carry live ports and parameter targets, compose through
`connect_subgraph_ports`, and re-save to the same semantic digest.
`inspect_document` refuses dangling members, a member claimed by two
instances, duplicate instance identities, malformed records, and records
outside the v6 envelope (`subgraph_*` refusals).

Since saved-identity v7 ([`G-3-v7-identity-design.md`](G-3-v7-identity-design.md))
the writer emits v7 and `members` name persisted authored node IDs; a v6
document with records still restores (its members bind through the load's
`identity_node_ids`), and `migrate_saved_document` translates its members.

Focused coverage is in `pulp-test-signal-graph-subgraph`. Gain and nested
Gain templates are exercised end to end; Processor-node members persist
through the existing Processor restore registry and the installed A2 consumer
(`examples/a2-modular-instrument-consumer`) replays them.

## Custom-node members (2026-11-17)

A `SubgraphNodeSpec` may be `NodeType::Custom`: it names a type registered on
the graph (`custom_type_id`) at an exact `custom_type_version`, with optional
initial opaque `custom_state`. Type-specific fields must be set exactly for
the node's own type. `instantiate_subgraph` refuses, before any graph change,
an unregistered type, a type registered only at another version, and initial
state the type does not accept. State is checked by
`detail::custom_member_state_accepted`: empty state is accepted; non-empty
state needs `create` and `load_state`, and a probe instance is created, given
the bytes and destroyed on the control thread. A throwing `create`,
`load_state` or `destroy` is a refusal, and the probe instance is always
destroyed.

Persistence keeps the v7 record format: members are authored node IDs in
expansion order, and the flattened node already carries the Custom type,
version and `state_b64`. Rebinding now also requires, per member, the exact
Custom type and version and port names (port kinds were already compared), the
exact Processor graph type and version (not only the descriptor), and Custom
state the registered type accepts (`subgraph_state_rejected`). Internal edges
are compared on every semantic `Connection` field (feedback, MIDI, automation,
audio-rate modulation, sidechain, spectral, Control, and the modulation target
and shape), not only endpoints and the feedback and MIDI flags. The writer
refuses an unresolved Custom member or state its type refuses, so it cannot
write a document the restore would refuse.

`from_saved_subgraph_document` now restores the whole document and rebinds
every record on a candidate graph that carries the caller's custom node types
(`GraphSerializer::copy_custom_node_types`) before it loads the caller's graph.
Template, membership, Custom type or version, state, and edge refusals
therefore leave the caller's graph exactly as it was. Only a second-pass
failure (a factory or restore callback that behaves differently the second
time) clears the graph, as any refused load does. Every refusal goes through
`detail::refuse_load`. Processor factories, restore registries and Custom state
probes therefore run more than once per restore, all on the control thread.
Records persist authored membership and identity only: no runtime NodeId,
prepared instance, voice generation or pending runtime event.

Evidence: `pulp-test-signal-graph-subgraph` (41 cases) covers expansion and
refusal of Custom members, a nested Custom round-trip with an audio replay
against the original graph and a fixed oracle, missing factory, other
registered version, refused state, altered membership, lost and re-roled
internal edges, the exact Processor graph type, a template past the nesting
limit, writer refusals, and injected `std::bad_alloc` in the candidate rebind,
the candidate flattened load, and the live rebind after the candidate passed
(`SubgraphPersistenceTestAccess`). The installed A2 consumer gains a stateful
Custom trim member, checks its exact type, version and state after restore,
includes the trim in its audio recurrence, and adds three planted refusals
(missing Custom type, another registered version, refused state) that must
leave the application's graph untouched.

## Typed event connections in the v7 document (2026-11-17)

Before this slice `GraphSerializer` did not persist the graph's event edge:
the writer emitted nothing for it and the loader reset it, so a saved
document lost the edge without a refusal. That is now closed.

Document format. `to_saved_document` writes an `event_connections` array
when the graph holds an event edge (`SignalGraph::connect_graph_event`).
Each record has exactly `producer` and `consumer` (authored IDs), and
`source_port`, `destination_port` and `kind`. A graph without an event edge
writes no member, so its document, digest and diff are unchanged. Only the
authored binding is saved: published host events, trigger traces and queue
contents are never persisted. The record is part of the semantic digest.
`to_json`, `to_file`, the spectral writer and the test-only v6 writer cannot
name endpoints by authored ID, so they refuse a graph that holds an event
edge instead of dropping it.

Inspection. `inspect_document` admits `event_connections` only in the v7
envelope and refuses a record that is malformed, has any other member, or
holds a port or kind outside 0..255 (`event_connection_invalid`), one that
names an identity the document does not bind (`event_connection_dangling`),
and an identical repeated record (`event_connection_duplicate`). A v6 or
plain document carrying the member is refused (`from_json` refuses it before
touching the graph), so v6 and earlier documents without it load exactly as
before.

Load. After every node takes its authored ID and every connection is
restored, each record is rebound through `connect_graph_event`, so the
graph's own rules apply unchanged (event-capable, non-transport Custom
endpoints, ports 0, kind 1, a feed-forward path, one edge per graph, no
parallel routing or anticipation). A refused binding fails the load with
`event_connection_not_restored` and names the binding result; the refusal
goes through `detail::refuse_load`, so the graph and every returned map are
emptied. An endpoint whose Custom type is not registered is refused rather
than loaded without its edge. `GraphSerializerTestAccess::fail_next_event_rebind`
injects `std::bad_alloc` in the rebind.

Diff and history. `diff_graph_documents` reports event connections by
authored identity and port in `event_connections_added`, `_removed` and
`_changed` (a kind change), includes them in its digest and in `equal()`,
and no longer treats them as an opaque section. `pulp graph diff` prints and
emits them. `GraphEditHistory` therefore records connecting an event edge as
an edit, and undo and redo restore it.

Subgraphs. `SubgraphTemplate::event_edge` declares one event connection
between two members (member keys, or `child.key` for a child member) with
ports and kind. Expansion binds it after every edge and rolls back on any
non-`Accepted` result with a specific `subgraph boundary:` rule; the bound
edge is reported in `SubgraphInstance::event_edge`. A Processor member is
refused as an endpoint (the graph binds only Custom endpoints), and since a
graph holds one event edge, a declaring template expands at most once per
graph. Rebind compares the template's declared edge, mapped through the
restored members, with the graph's edge and refuses a lost or re-pointed
edge and an undeclared edge between two members
(`subgraph_instance_mismatch`). `to_saved_subgraph_document` refuses the same
states, so it never writes a document its restore refuses.
`from_saved_subgraph_document` now takes the candidate path for any document
with event connections, records or not, so a binding refusal leaves the
caller's graph untouched.

Evidence: `pulp-test-graph-event-persistence` covers the round trip with an
audio replay oracle (the restored consumer renders the producer's payload; a
graph without the edge renders none), exact re-save, writer refusals of the
plain, file and v6 formats, v6 and plain compatibility with smuggled-record
refusals, planted dangling, duplicate, second distinct record, kind, non-event
endpoint and malformed records against a positive control, the injected
rebind failure, diff and digest by authored identity across NodeId
renumbering, undo and redo, and the subgraph declaration, nested child
declaration, Processor endpoint, second instance, unknown key, lost,
re-pointed and undeclared restore refusals, and writer refusals.

## Fixed-count voice-template declarations (2026-11-17)

`pulp/host/subgraph_persistence.hpp` adds a voice declaration: one
`SubgraphTemplate` expanded as N identical voices, with N in
1..`kMaxSubgraphVoices` (16). `instantiate_subgraph_voices` checks the
declaration identity (1..128 bytes, no control characters), the count and the
template identity before touching the graph, then expands voice k as an
ordinary subgraph instance with instance identity
`subgraph_voice_identity(identity, k)` ("<identity>.voice.<k>") and instance
index k. A voice that fails to expand removes every voice the call built.
Voice identities are derived from the declaration, never chosen by the
loader, and distinct (declaration, voice) pairs give distinct identities.

Document format. `to_saved_subgraph_document` gains an overload that takes
voice banks. Each voice is written as an ordinary `subgraphs` record (so the
existing membership, liveness, parameter and Custom checks apply), and each
bank as a `voice_declarations` entry with exactly `identity`,
`template_identity`, `voice_count` and `voices` (the derived identities, in
voice order). The writer refuses a malformed declaration, a count outside the
bound or different from its voices, a voice without its derived identity,
index and the declared template, a voice holding an event connection, two
banks with one identity, and a voice that is also passed as a plain instance.
Only the declaration and the voices' declared parameter values persist.
Sounding voices, allocator state, note tokens, epochs, pedal holds and
release tails are never written.

Inspection. `inspect_document` admits `voice_declarations` only in the v7
envelope (a v6 or plain document carrying it is refused, so v6 and earlier
documents without it load exactly as before) and refuses, reusing the
subgraph refusal codes: a malformed entry, an unknown member, a count outside
1..16 or different from the listed voices, a voice identity that is not the
derived one, and a record with another template or index
(`subgraph_record_invalid`); a repeated declaration identity or a voice
identity listed twice (`subgraph_binding_duplicate`); and a declared voice
with no record (`subgraph_binding_dangling`).

Restore. `from_saved_subgraph_document` rebinds voice records like any record
(template lookup, member structure, internal edges, parameter bounds) on the
candidate graph first, then moves each declared voice into
`SubgraphDocumentLoad::voice_banks` (ordered by declaration identity, voices
in voice order); voices do not also appear in `subgraphs`. A voice template
that declares an event connection is refused as `subgraph_instance_mismatch`.
Every refusal goes through `detail::refuse_load` and, being found on the
candidate, leaves the caller's graph untouched. The plain
`GraphSerializer::from_saved_document` reader loads the flattened voices and
ignores the declaration, as it ignores subgraph records.

Limit. A graph binds one event connection, so per-voice event wiring is not
representable: a template that declares an event connection (itself or in a
child) is refused by expansion, the writer and the restore, even for one
voice. Voices carry audio and parameters only. The declaration is not yet
bound to the `VoiceBankBinding` runtime or its eight-slot manifest; voice
allocation is unchanged.

Diff and history. Voice members are ordinary nodes, so
`diff_graph_documents` reports added voices by authored identity and a
per-voice value edit as one changed node; the `voice_declarations` and
`subgraphs` sections are compared verbatim (they hold only authored
identities, so NodeId renumbering does not change them) and appear in
`sections_changed`. `GraphEditHistory` records expanding a bank as one edit;
undo removes every voice member and redo restores each by authored ID. History
does not rebind instance handles; a caller re-derives them by restoring the
subgraph document.

Evidence: `pulp-test-subgraph-voices` (6 cases) covers expansion with derived
identities, count, identity and template refusals with bound controls, the
rollback of earlier voices when a later one fails, the round trip through the
public save and load path with an audio render across three voices of
distinct power-of-two gains (0.875, and 0.625 after one voice is muted), exact
re-save, a plain instance beside a bank, v6 compatibility and the refused v6
smuggle, planted count 0, count over the bound, count and list mismatch, a
voice listed twice, a repeated declaration, a non-derived voice identity, a
missing record, a template mismatch, an unknown member, a missing template and
two member-key mismatches against an unedited positive control, the writer
refusals, and diff and undo or redo by authored identity.
`pulp-test-graph-event-persistence` adds the event template refusal at
expansion, restore and writer, with positive controls.

## G-4 voice binding schema and persistence slice (2026-11-06)

The public `pulp/host/voice_template.hpp` schema now validates a versioned authored binding manifest, deterministically expands exactly eight isolated slot records, and emits stable G-4 identities independent of runtime node IDs. `VoiceBankState` persists only declared finite per-slot parameters; save/restore is transactional and rejects stale identity, duplicate/aliased paths, cross-slot mutable declarations, mismatched bindings, unsupported migration, and non-finite values. Focused positive and planted-negative evidence is recorded in [`g4-voice-binding-persistence-receipt-20261106.md`](../evidence/g4-voice-binding-persistence-receipt-20261106.md). This remains a control-side schema and persistence receipt only; G-5 host ingress, A1 audio/tail oracle, installed-consumer evidence, and all graph voice runtime remain HOLD.


This slice adds a declarative `SubgraphTemplate` for built-in Input, Output, and
Gain nodes. A template declares named exposed ports, parameter paths, and
feed-forward edges. `instantiate_subgraph` expands an instance into the existing
`SignalGraph` authoring plan; it does not add a second scheduler or runtime.

Nested macros are now supported as a bounded extension. A child template is
value-owned by `SubgraphChildSpec`, recursively flattened into the same plan,
and addressed by a deterministic `child.port` / `child.parameter` namespace.
Child identity and instance index are retained in `SubgraphState`; a mismatched
child identity, index, duplicate key, cycle, or depth overflow is rejected at
the subgraph boundary before a graph is published. Parent declarations can
promote child ports and connect them to local built-in endpoints without
inspecting runtime node IDs.

Each expansion receives an explicit instance identity and index. The returned
`SubgraphInstance` owns the instance-local node and port handles and can save or
restore declared parameter state. State restore checks template identity,
instance identity, and instance index before applying values. Failed edge,
node, port, or parameter validation returns a `GraphResult` whose rule is
prefixed `subgraph boundary:` and rolls back nodes created by the expansion.
Parameter targets are checked against the template before graph mutation: only
Gain nodes and Processor nodes (`NodeType::Plugin` with a `processor_factory` and
an exact descriptor identity) are accepted. Input and Output targets return a
boundary error without
changing existing nodes, connections, or the next allocated node ID. Regression
coverage includes both rejected node types and successful Gain default/restore.

The current boundary is intentional: plugin, custom-node, event, and polyphony
children remain future slices. This API establishes deterministic nested
identity and diagnostics for built-in control-thread templates only. Focused
coverage is in `pulp-test-signal-graph-subgraph`.

Repair validation (2026-11-03): the governed Release build passes all 12 focused
cases (88 assertions). `confirm_failure.sh` verifies the suite passes with target
prevalidation, fails when that check is disabled, and passes after restoration,
with the changed source recompiled in each phase. Full CI remains required; the
local gate host refuses heavy source-selftest and diff-coverage lanes by policy.

Identity follow-up (2026-11-04): `pulp/host/voice_identity.hpp` adds a value-only
G-4 v1 canonical key for template namespace/name/revision, bank schema, slot,
path, and optional exposed port/parameter targets. It NFC-normalizes and rejects
control characters, embedded NUL, slash-ambiguous segments, unsupported port
tags, and slot ordinals outside the eight-slot A1 bank, then emits the tagged
length-delimited big-endian encoding and its portable SHA-256 digest. The API
contains no runtime node IDs, allocator indexes, epochs, or note generations;
it therefore establishes the persistence identity seam without claiming graph
voice runtime, migration, realtime, or G-6 completion. Focused coverage is in
`pulp-test-voice-identity` (22 assertions, including planted refusals).

Composition follow-up (2026-11-05): `connect_subgraph_ports` composes two
`SubgraphInstance` values by their exposed names. It validates declaration,
output/input direction, and `PortKind` before mutation, then resolves the
instance-local aliases to the graph's canonical port names before delegating to
the ordinary `SignalGraph` connection checks. Missing, wrong-direction, and
kind-mismatch controls leave topology unchanged. The graph-spatial cookbook
now includes a source-to-sink composition and renders a 0.125 impulse through
the two gain stages; its missing and wrong-direction controls are planted
negatives. This remains control-thread graph authoring and offline render
evidence; it does not add nested templates, event routing, scheduling,
realtime, or G-3 fingerprint behavior.

Nested-macro follow-up (2026-11-06): the public installed-SDK cookbook now
expands a source-stage child through a parent template, promotes its exposed
ports, restores `inner.gain`, and rejects a planted child-identity mutation.
The focused source test also rejects cyclic and duplicate-key declarations
before graph mutation. This is control-thread flattening and offline render
evidence only; G-3 whole-graph semantic/resolved fingerprints and undo remain
PARTIAL, while G-5 event ingress/timing and realtime qualification remain
outside this slice.

Voice-bank readiness fixture (2026-11-06): the focused source suite now
expands exactly eight independent instances with the public template API and
checks that each exposed port and gain target is instance-local. It pairs each
slot with the existing G-4 canonical voice identity helper, verifies unique
slot digests and repeatable encoding, and restores one slot while checking that
the other seven gains remain unchanged. A stale instance identity is rejected
without changing the live slot. This is a bounded identity and state-isolation
fixture for A1; it does not add a voice-bank runtime, event ingress, migration,
realtime, or G-6 audio-oracle claim.
