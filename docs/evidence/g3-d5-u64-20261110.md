# G3 D5 exact unsigned-integer repair — 2026-11-10

This handoff repairs the bounded D5 resolved identity and receipt paths so every
`uint64_t` admission limit has an exact canonical decimal representation, including
actual `SIZE_MAX` host limits on a small prepared stereo graph. It introduces no
new graph profile, public Pulp API, scheduler, or saved-envelope support.

Base commit: `a7103a43d06c0101048ed0def80809d8ef5ac1d3`.
Branch: `feature/g3-resolved-u64-20261110`.
Implementation-only binary Git patch SHA-256:
`6766afa590c3e4306175899c0ea5e9972a91376ede94923d0ecc3b28dd3dda62`
(the eight source/test/patch files, before this evidence document).
Host: `Daniels-Mac-Studio-m3`, macOS arm64.

The private host conversion represents the unsigned upper half using a CHOC object
class that wire JSON objects cannot create. A source-owned, opt-in CHOC numeric
conversion hook receives each original numeric token before either `strtoll` or
`strtod`; the existing CHOC entry points retain their default behavior. D5 uses
this path for projection validation, receipt assembly, and receipt decoding.
The canonical encoder emits every accepted integer through `to_chars(uint64_t)`.
Narrower field bounds, effective-limit minima, and zero hard-cap refusals remain.
