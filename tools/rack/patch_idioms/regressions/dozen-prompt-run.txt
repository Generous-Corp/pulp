# was not the model. Every failure in between was the checker rejecting a
# correct patch, or the generator being told nothing about the thing it got
# wrong:
#
#   - the kick's VCA was set to level 0 and went silent, because the model was
#     shown every module's ports and nothing about its params -- no names, no
#     ranges, no defaults -- and a level knob multiplies its CV.
#   - a gate relayed through a multiple was asked to look like a gate at the
#     MULT's own jack, which is role Cv whatever is fed into it.
#   - an envelope reaching an oscillator's V/OCT was wanted at a cv_in; our
#     manifests call that jack Pitch and the vendor inference calls it Cv.
#   - an oscillator reaching a filter through a mixer, and a register reaching
#     a pitch input through a quantizer, were read as never arriving.
#
# The last two failed INTERMITTENTLY across runs, because whether they fire
# depends on which of several correct patches the model happens to write. A
# pass rate that moves with no code change is a checker problem, not a model
# problem.
